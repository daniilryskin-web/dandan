# Advanced-чарт DataLens: состав услуг по ОЦС и ДК

Состав целого («ВСЕГО услуг») раскладывается на причины выбытия и оставшиеся —
отдельной полосой на каждый трек, ОЦС и ДК. Итог стоит в шапке справа.

## Раскладка по вкладкам

| Файл | Вкладка |
|---|---|
| `Meta.json` | Meta |
| `Params.js` | Params |
| `Sources.js` | Sources |
| `Prepare.js` | Prepare |
| `Controls.js` | Controls |

## Подключение датасета

Во вкладку **Meta** обязательно вписывается id датасета:

```json
{"links": {"compositionDataset": "<id из адреса .../datasets/ID>"}}
```

Измерения у этого чарта нет: `Sources.js` запрашивает восемь скалярных мер, и
запрос без измерения возвращает одну строку с итогами. Имена полей должны
совпадать с датасетом дословно; у каждого поля в `SEGMENTS` есть запасные
имена с суффиксом «(индикатор)».

## Сегменты и формула

Полоса каждого трека складывается из пяти частей (`SEGMENTS`):

| Сегмент | ОЦС | ДК |
|---|---|---|
| ЛиР (ниже не приводятся) | общее поле | общее поле |
| Не требуется | `Не требуется ОЦС` | `Не требуется ДК` |
| Перенос на 2027 | `Перенос на 2027 ОЦС` | `Перенос на 2027 ДК` |
| Исключены работы в 2026 | `Исключены работы в 2026 ОЦС` | `Исключены работы в 2026 ДК` |
| Оставшиеся | считается | считается |

«Оставшиеся» не запрашиваются из датасета, а считаются как остаток —
`ВСЕГО услуг` минус все предыдущие сегменты. Это ровно ваша формула:

```
Оставшиеся ОЦС = ВСЕГО услуг − ЛиР − Не требуется ОЦС
               − Перенос на 2027 ОЦС − Исключены работы в 2026 ОЦС
Оставшиеся ДК  = ВСЕГО услуг − ЛиР − Не требуется ДК
               − Перенос на 2027 ДК − Исключены работы в 2026 ДК
```

Считать остатком, а не брать готовым полем, здесь надёжнее: полоса по
построению всегда сходится к «ВСЕГО услуг», и состав не может тихо разъехаться
с итогом.

Обе полосы меряются одной шкалой — иначе треки нельзя было бы сравнивать
глазами.

## Когда что-то не сходится

* поля нет в ответе — его имя выводится подписью под заголовком, а сегмент
  считается нулевым: без подписи недостающая мера молча превратилась бы в ноль
  и выглядела как настоящие данные;
* сумма вычитаемых больше базы (остаток ушёл бы в минус) — чарт не рисует
  полосы и пишет, что проверить: отрицательный сегмент нарисовать нельзя, а
  молча обрезать его до нуля значит соврать;
* сегмент, нулевой у обоих треков, в легенду не попадает — пустая строка
  легенды ничего не сообщает;
* итог трека подписывается у конца полосы, только если он разошёлся с базой.
  При сходящейся формуле это было бы одно и то же число трижды.

## Цифры

Значение стоит внутри своего сегмента. Узкий сегмент расширяется ровно до
ширины подписи, недостающие пиксели снимаются с крупных пропорционально их
запасу — общая длина полосы не меняется. `fitLabels: false` выключает
подгонку.

Цвет подписи выбирается по контрасту с заливкой. Скруглены только внешние
концы полосы, между сегментами просвет 2 px.

## Палитра

| Сегмент | Цвет |
|---|---|
| ЛиР (ниже не приводятся) | `#8E7CF2` |
| Не требуется | `#4A38AD` |
| Перенос на 2027 | `#C0397E` |
| Исключены работы в 2026 | `#8A6A00` |
| Оставшиеся | `#4B2DE8` |

Набор проверен по соседним парам (худшая — ΔE 11.7 при протанопии, 22.2 при
нормальном зрении). Самый насыщенный цвет отдан «Оставшимся»: это главная
часть состава, остальное — причины выбытия.

## Проверка

```
node dev/check.js               # изоляция рендера + четыре размера холста
node dev/preview.js 960 280     # обновляет preview.html
```

## Что проверено

* Рендер в Chromium на 960×280: обе полосы сходятся к 237, у ДК получается
  65 / 17 / 155 — как на вашем скриншоте.
* Отсутствующее поле: сегмент обнуляется, имя поля выводится подписью,
  остаток пересчитывается.
* Вычитаемые больше базы: чарт пишет, что проверить, вместо отрицательной
  полосы.
* Нет базы, пустой ответ, пустая строка в ответе — каждый случай даёт своё
  объяснение, а не падение.
* `dev/check.js` проходит на четырёх размерах холста.

Не проверено вживую (нет доступа к инстансу DataLens): поведение
`Editor.generateHtml` на SVG-разметке и точные имена полей.
