# 10. Дерево структуры: сборка Advanced-чарта в DataLens

Полная инструкция по одному чарту: код каждой вкладки редактора, порядок
заполнения, размещение на дашборде и разбор сбоев.

Результат — дерево «Ответственный за направление → Проект → Руководитель →
Продукт» с составом команды по уровням ролей на каждом узле.

Ориентировочное время — 20–30 минут.

---

## Часть 0. Как устроен Advanced-чарт

Это важно понять до того, как копировать код, иначе половина инструкции
покажется произвольной.

**Advanced-чарт — это не конфигуратор графика.** У него нет ни осей, ни
серий, ни настроек визуализации. Он рисует то, что вы вернули из функции
`render`, — HTML или SVG с безопасной разметкой.

**Код исполняется в двух разных местах:**

| Где | Что там можно | Что там нельзя |
|---|---|---|
| **Сервер** — весь код вкладки Prepare вне `wrapFn` | обращаться к данным через `Editor.getLoadedData()`, считать, группировать, сортировать | ничего рисовать |
| **Клиент** — функция `fn` внутри `Editor.wrapFn` | собирать разметку из того, что пришло аргументом | обращаться к DOM, к браузерным API, к внешним переменным |

Функция `fn` работает в песочнице QuickJS. Она **не видит переменных
файла** — всё, что ей нужно, передаётся списком `args`. Поэтому чарт
устроен так: на сервере считается дерево и раскладка, на выходе получается
`scene` — плоский список готовых прямоугольников и линий; на клиенте из
него собирается строка SVG.

Ограничения платформы, о которые можно споткнуться:

- 10 секунд на выполнение вкладки Prepare;
- 50 Мбайт данных из одного источника, 100 Мбайт из всех;
- доступные библиотеки — только `d3`, `d3-chord`, `d3-sankey`, `date-utils`.
  **Highcharts недоступен.** Дерево обходится без библиотек вообще: SVG
  собирается строкой.

**Вкладок пять, все принимают только код:** Meta, Params, Sources, Prepare,
Controls. Вкладка Config для Advanced-чарта не показывается — она есть
только у типов «График (Gravity UI Charts)» и «Таблица».

## Часть 1. Что должно быть готово

1. Запущен `prepare_dataset.py`, рядом лежит **`datalens_dataset_tree.csv`**
   (57 строк).
2. На листе «Проверки» в строке «Расхождение ФОТ, руб» стоит **0**.
3. Создан датасет **`HR · Иерархия`** — части 1.1–1.3 из
   [`08-hierarchy-tab.md`](08-hierarchy-tab.md).

Датасет должен содержать тринадцать полей:

```
Блок · Проект · Руководитель · Продукт кратко · риск
R4 · R3 · R2 · R1 · R0 · людей · вакансий · ФОТ_мес
```

**Скопируйте id датасета** — он понадобится на первой же вкладке. Откройте
датасет → меню → **Копировать ID**. Он же виден в адресной строке:
`…/datasets/<вот_это>/…`.

---

## Часть 2. Создать чарт

**Чарты → Создать чарт → Редактор → Advanced-чарт.**

Откроется редактор с вкладками Meta, Params, Sources, Prepare, Controls.
Заполнять их нужно **в этом порядке**: Sources ссылается на алиас из Meta,
Prepare работает с тем, что вернул Sources.

---

## Часть 3. Вкладка Meta

Перечень связанных сущностей. Ключ — произвольный алиас, значение — id
датасета. По этим id DataLens понимает, с чем связан чарт: без них не
работают диалог связанных объектов, копирование воркбука и публикация.

Файл: [`editor/structure-tree.meta.js`](editor/structure-tree.meta.js)

```js
{
    "links": {
        "hrTree": "ЗАМЕНИТЕ_НА_ID_ДАТАСЕТА"
    }
}
```

Одна тонкость: **здесь не пишут `module.exports`** — вкладка принимает
голый объект. На остальных вкладках, наоборот, `module.exports` обязателен.

---

## Часть 4. Вкладка Params

Параметры чарта по умолчанию. Значения — **массивы строк**, даже когда
значение одно: `count: ['10']`, а не `count: 10`. Всё, что должно приходить
из селекторов дашборда или из URL, обязано быть объявлено здесь.

Дерево строится по всем данным, а фильтруется селекторами дашборда на
уровне датасета, поэтому собственных параметров ему не нужно.

Файл: [`editor/structure-tree.params.js`](editor/structure-tree.params.js)

```js
module.exports = {};
```

Пустой объект — рабочее значение, но вкладку нельзя оставить незаполненной.

---

## Часть 5. Вкладка Sources

Запрос к датасету. Алиас `hrTree` берётся из Meta через `Editor.getId`.

Файл: [`editor/structure-tree.sources.js`](editor/structure-tree.sources.js)

```js
function field(title) {
    return { ref: { type: 'title', title: title } };
}

module.exports = {
    tree: {
        datasetId: Editor.getId('hrTree'),
        data: {
            fields: [
                field('Блок'),
                field('Проект'),
                field('Руководитель'),
                field('Продукт кратко'),
                field('риск'),
                field('R4'),
                field('R3'),
                field('R2'),
                field('R1'),
                field('R0'),
                field('людей'),
                field('вакансий'),
                field('ФОТ_мес')
            ]
        }
    }
};
```

Это канонический формат из документации. Короткая запись через
`require('libs/dataset/v2')` делает то же самое, но зависит от версии
служебного модуля, которого в части инсталляций нет; она оставлена
в файле закомментированной.

**Главная ловушка здесь.** Значения `title` должны совпадать с названиями
полей в датасете **побуквенно, включая регистр**:

```
людей      — не «Людей»
вакансий   — не «Вакансий»
риск       — не «Риск»
ФОТ_мес    — с подчёркиванием, не «ФОТ мес»
```

Если хоть одно не совпадёт, источник вернёт пустой результат **без ошибки**.
Именно из-за этого чарт может нарисовать одну легенду и ничего больше.
Сверьте названия, открыв датасет.

Порядок полей задаёт порядок колонок в ответе и продублирован константой
`COLUMNS` на вкладке Prepare.

## Часть 6. Вкладка Prepare

Основной код. Открыть
[`editor/structure-tree.prepare.js`](editor/structure-tree.prepare.js),
скопировать **целиком**, вставить.

Файл заканчивается так — это и есть обязательная структура Advanced-чарта:

```js
module.exports = {
    render: Editor.wrapFn({
        fn: function (options, scene) {
            // ...собираем SVG-строку из scene...
            return Editor.generateHtml('<div style="…">' + svg + '</div>');
        },
        args: [scene]
    })
};
```

Первым аргументом `fn` всегда приходят размеры виджета: `options.width`
и `options.height`. Дерево оборачивается в `div` с `overflow:auto` ровно
этого размера — иначе DataLens обрежет полотно по ячейке дашборда, а не
прокрутит его.

Настройки вынесены в начало файла:

```js
var ROW    = 34;                    // высота строки
var COL_X  = [0, 214, 434, 648];    // отступ уровня от левого края
var NODE_W = [200, 206, 200, 396];  // ширина узла по уровням
var NODE_H = 30;                    // высота узла
var STRIP  = 5;                     // толщина полосы состава
```

Полотно получается **1068 × 1984 px** при 57 строках. Высоту виджета
подбирать под него не надо — прокрутка внутри уже есть.

## Часть 7. Вкладка Controls

Элементы управления внутри самого чарта. Живут отдельно от селекторов
дашборда, влияют только на этот чарт и сбрасываются при перезагрузке
страницы. Дереву не нужны.

Файл: [`editor/structure-tree.controls.js`](editor/structure-tree.controls.js)

```js
module.exports = {};
```

## Часть 8. Сохранить и проверить

Сохранить под именем `Структура работ`. Чарт отрисуется прямо в редакторе.

- [ ] четыре колонки узлов слева направо;
- [ ] четыре тёмных узла направлений: Ульянов, Зазыкин, Богданова, Радужан;
- [ ] на каждом узле полоса и бейдж вида `25-21-8-14-13`;
- [ ] у Ульянова А.Ю. — **81 чел**, бейдж `25-21-8-14-13`
      (25 + 21 + 8 + 14 + 13 = 81);
- [ ] узлов-руководителей ровно **18**;
- [ ] красных рамок **8**, жёлтых **18**;
- [ ] дерево прокручивается внутри чарта.

> Восемь красных и восемнадцать жёлтых — это счёт **узлов**, а не продуктов.
> Продуктов на одном-двух людях 24 из 56; разницу даёт ФССП, которую ведут
> два руководителя: она попадает в дерево дважды — узлом на 2 человека
> (жёлтый) и узлом на 1 человека (красный).

## Часть 9. Положить на дашборд

1. Дашборд → **Добавить → Чарт** → `Структура работ`.
2. Растянуть виджет **на всю ширину** вкладки: дерево шириной 1068 px,
   в узком виджете к вертикальной прокрутке добавится горизонтальная.
3. Высота — любая удобная, 600–800 px. Прокрутка внутри чарта уже есть,
   подгонять высоту под полотно не нужно.
4. Ничего рядом не ставить.

### Селекторы

Селекторы «Блок» и «Проект» фильтруют дерево как обычный чарт датасета.
Если селектор построен на другом датасете, **связь проставляется руками**:
вкладка → **Связи** (иконка цепочки справа вверху) → для «Блок» связь
`по полю Блок` с чартом `Структура работ`. То же для «Проект».

Проверка: выбрать одно направление — в дереве должна остаться одна ветка.

## Часть 10. Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| «Не удалось получить id» на Sources | алиас не описан в Meta или опечатка | сверить ключ в Meta и в `Editor.getId()` |
| Пусто, ошибок нет | так больше не бывает: чарт покажет панель с причиной | читать панель |
| «Нет колонки «ФОТ_мес». Пришли: …» | колонка не запрошена в Sources или переименована в датасете | добавить в `columns`, проверить название в датасете |
| Отрисовалась только легенда | старая версия кода | обновить Prepare: теперь вместо легенды рисуется панель с причиной |
| Дерево обрывается на середине | сработал лимит строк | добавить в `buildSource` параметр `limit: 1000` |
| Превышено время выполнения Prepare | 10 секунд на вкладку | уменьшить число строк в источнике |
| Разметка отрисовалась текстом | забыт `Editor.generateHtml` | вернуть строку через него — без обёртки всё экранируется |
| Название налезает на числа справа | длинные названия продуктов | увеличить `NODE_W[3]` или `TITLE_CH` |

**Чарт диагностирует себя сам.** Если данных нет, не хватает колонки или
значения не читаются, вместо дерева рисуется панель «Дерево не построено» —
с причиной, журналом разбора и списком того, что проверить.

Журнал показывает, например:

```
Ключи источников: tree
Ключи внутри «tree»: notifications, data_export_forbidden, result_data, fields, …
Формат: result_data[0].rows, строк — 57
Строка — объект data + legend, значений: 13
Колонки: Блок · Проект · Руководитель · Продукт кратко · риск · R4 · …
Первая строка: Ульянов А.Ю. · Забота и сопровождение · Бирюкова В.В. · …
```

Шесть строк отвечают на всё: дошёл ли запрос, в каком формате ответ,
сколько строк, как устроена строка, как называются колонки и что в них
лежит на самом деле.

Разбор умеет четыре вида строки и определяет их сам:

| Вид строки | Где встречается |
|---|---|
| `[значение, ...]` | ответ через `result.data.Data` |
| `{values: [...]}` | старый формат |
| `{data: [...], legend: [...]}` | текущий формат DataLens |
| `{Блок: '…', Проект: '…'}` | объект с ключами-названиями |

Отдельно сверяется число колонок с числом значений в строке: `fields`
в ответе может описывать весь датасет, а не только запрошенные поля,
и тогда имена не совпали бы со значениями по позиции. В этом случае
берётся порядок, объявленный в `COLUMNS`.

## Что этот чарт не умеет

- **Кликов и тултипов нет.** Вся информация на узле. Тултипы в
  Advanced-чарте возможны — через тег `dl-tooltip` или блок `tooltip`
  рядом с `render`, — но здесь не заводились.
- **Тёмная тема не поддерживается**: цвета заданы явно в `THEME`. При
  желании их можно перевести на CSS-переменные с префиксом `--ce-theme`,
  которые DataLens подставляет под текущую схему.
- **Переименование поля в датасете ломает чарт.** Он покажет понятную
  ошибку со списком пришедших колонок, но чинить придётся в коде.
- **Это дерево структуры работ, а не подчинённости.** Дерево «кто кому
  подчиняется» строится тем же кодом, но требует столбца `ID руководителя`
  в той же нумерации, что и `ФИО (штат)`.

## При обновлении данных

Код трогать не нужно: замените файл в подключении `hr_tree`, чарт
перечитает датасет сам, высота полотна пересчитается. Правка нужна только
при изменении состава столбцов — тогда синхронно меняются `columns`
на Sources и `COLUMNS` на Prepare.
