# Advanced-чарт DataLens: заявки по типам услуг

Девятый чарт набора: горизонтальный стек «0. Заявка не подана / 1. Заявка
подана / 2. Заявка исполнена:» по типам услуг, сумма в конце полосы.

Рендер тот же, что в `../mincifry_bar_chart` — отличаются константы и две
добавки под длинные подписи (см. ниже). Это отдельная сущность в DataLens,
поэтому набор вкладок свой; палитра продублирована, менять цвета придётся во
всех копиях.

## Раскладка по вкладкам

| Файл | Вкладка |
|---|---|
| `Meta.json` | Meta |
| `Params.js` | Params |
| `Sources.js` | Sources |
| `Prepare.js` | Prepare |
| `Controls.js` | Controls |

## Подключение датасета

Во вкладку **Meta** обязательно вписывается id датасета:

```json
{"links": {"requestsDataset": "<id из адреса .../datasets/ID>"}}
```

Поле категории — `Тип`. Меры запрашиваются с суффиксом «(индикатор)» и
двоеточием в конце третьей — имена должны совпадать с датасетом дословно.

У серий есть `aliases`: если те же меры окажутся без суффикса, чарт возьмёт
их. В легенде показывается `label` — имя без «(индикатор)».

## Порядок категорий

Задан списком:

```js
const CATEGORY_ORDER = ['Услуг ИЭП', 'Услуг Гостех'];
```

Список надёжнее сортировки: по алфавиту «Услуг Гостех» встало бы перед «Услуг
ИЭП», а в вашем чарте наоборот. Категории, которых в списке нет, идут следом
в порядке источника.

Колонка подписей считается по самой длинной подписи и ограничена
`maxLabelWidth` (220 px) и третью ширины холста; что не влезло — усекается
многоточием, полный текст в подсказке.

## Цифры и итоги

Как в парном чарте: значение стоит внутри своего блока, узкий сегмент
расширяется ровно до ширины подписи, недостающие пиксели снимаются с крупных,
общая длина полосы не меняется. Итог — справа от полосы. Сегменты с нулём не
рисуются: у «1.3 Обр» нулевой «Рефакторинг», в визарде он давал одинокий «0»
у оси.

## Проверка

```
node dev/check.js                # изоляция рендера + четыре размера холста
node dev/preview.js 1000 620     # обновляет preview.html
```

## Что проверено

* Рендер прогнан в Chromium на 1000×320: значения 28 / 34 / 14 и 51 / 25 / 14
  стоят внутри своих блоков, итоги 76 и 90 — в конце полос.
* Порядок: строки в `dev/fixture.js` лежат в обратном порядке — чарт
  расставляет их по `CATEGORY_ORDER`.
* Узкий холст 480×520: колонка подписей ограничена третью ширины, полосы не
  исчезают. На такой ширине у самых коротких сегментов цифры не помещаются и
  не рисуются — это тот же честный запасной вариант, что и в парном чарте.
* `dev/check.js` проходит на четырёх размерах холста.

Не проверено вживую (нет доступа к инстансу DataLens): поведение
`Editor.generateHtml` на SVG-разметке.
