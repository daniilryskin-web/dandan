# 10. Дерево структуры: сборка Advanced-чарта в DataLens

Полная инструкция по одному чарту: код каждой вкладки редактора, порядок
заполнения, размещение на дашборде и разбор сбоев.

Результат — дерево «Ответственный за направление → Проект → Руководитель →
Продукт» с составом команды по уровням ролей на каждом узле.

Ориентировочное время — 20–30 минут.

---

## Часть 0. Как устроен Advanced-чарт

Это важно понять до того, как копировать код, иначе половина инструкции
покажется произвольной.

**Advanced-чарт — это не конфигуратор графика.** У него нет ни осей, ни
серий, ни настроек визуализации. Он рисует то, что вы вернули из функции
`render`, — HTML или SVG с безопасной разметкой.

**Код исполняется в двух разных местах:**

| Где | Что там можно | Что там нельзя |
|---|---|---|
| **Сервер** — весь код вкладки Prepare вне `wrapFn` | обращаться к данным через `Editor.getLoadedData()`, считать, группировать, сортировать | ничего рисовать |
| **Клиент** — функция `fn` внутри `Editor.wrapFn` | собирать разметку из того, что пришло аргументом | обращаться к DOM, к браузерным API, к внешним переменным |

Функция `fn` работает в песочнице QuickJS. Она **не видит переменных
файла** — всё, что ей нужно, передаётся списком `args`. Поэтому чарт
устроен так: на сервере считается дерево и раскладка, на выходе получается
`scene` — плоский список готовых прямоугольников и линий; на клиенте из
него собирается строка SVG.

Ограничения платформы, о которые можно споткнуться:

- 10 секунд на выполнение вкладки Prepare;
- 50 Мбайт данных из одного источника, 100 Мбайт из всех;
- доступные библиотеки — только `d3`, `d3-chord`, `d3-sankey`, `date-utils`.
  **Highcharts недоступен.** Дерево обходится без библиотек вообще: SVG
  собирается строкой.

**Вкладок пять, все принимают только код:** Meta, Params, Sources, Prepare,
Controls. Вкладка Config для Advanced-чарта не показывается — она есть
только у типов «График (Gravity UI Charts)» и «Таблица».

## Часть 1. Что должно быть готово

1. Запущен `prepare_dataset.py`, рядом лежит **`datalens_dataset_tree.csv`**
   (218 строк — одна на пару «продукт — сотрудник», 58 карточек).
2. На листе «Проверки» в строке «Расхождение ФОТ, руб» стоит **0**.
3. Создан датасет **`HR · Иерархия`** — части 1.1–1.3 из
   [`08-hierarchy-tab.md`](08-hierarchy-tab.md).

Датасет должен содержать шестнадцать полей:

```
Блок · Проект · Руководитель · Продукт кратко · риск
R4 · R3 · R2 · R1 · R0 · людей · вакансий · ФОТ_мес
заместитель · команда · Сотрудник
```

Последние три необязательные: без них дерево работает, просто не покажет
заместителя, не будет раскрывать состав по клику и не даст выпадающий
селектор сотрудников.

**Скопируйте id датасета** — он понадобится на первой же вкладке. Откройте
датасет → меню → **Копировать ID**. Он же виден в адресной строке:
`…/datasets/<вот_это>/…`.

## Часть 2. Создать чарт

**Чарты → Создать чарт → Редактор → Advanced-чарт.**

Откроется редактор с вкладками Meta, Params, Sources, Prepare, Controls.
Заполнять их нужно **в этом порядке**: Sources ссылается на алиас из Meta,
Prepare работает с тем, что вернул Sources.

---

## Часть 3. Вкладка Meta

Перечень связанных сущностей. Ключ — произвольный алиас, значение — id
датасета. По этим id DataLens понимает, с чем связан чарт: без них не
работают диалог связанных объектов, копирование воркбука и публикация.

Файл: [`editor/structure-tree.meta.js`](editor/structure-tree.meta.js)

```js
{
    "links": {
        "hrTree": "ЗАМЕНИТЕ_НА_ID_ДАТАСЕТА"
    }
}
```

Одна тонкость: **здесь не пишут `module.exports`** — вкладка принимает
голый объект. На остальных вкладках, наоборот, `module.exports` обязателен.

---

## Часть 4. Вкладка Params

Параметры чарта по умолчанию. Значения — **массивы строк**, даже когда
значение одно: `count: ['10']`, а не `count: 10`. Всё, что должно приходить
из селекторов дашборда или из URL, обязано быть объявлено здесь: незаявленный
параметр просто не дойдёт до чарта.

Пять параметров — это пять селекторов дашборда, шестой (`search`) —
поле ввода в шапке чарта. Пустой массив означает «все», то есть без
фильтра.

Файл: [`editor/structure-tree.params.js`](editor/structure-tree.params.js)

```js
module.exports = {
    block: [],
    project: [],
    chief: [],
    product: [],
    employee: [],
    search: ['']
};
```

| Параметр | Колонка | Откуда приходит |
|---|---|---|
| `block` | `Блок` | селектор «ответственный за направление» |
| `project` | `Проект` | селектор «направление» |
| `chief` | `Руководитель` | селектор «руководитель продукта» |
| `product` | `Продукт кратко` | селектор «продукт» |
| `employee` | `Сотрудник` | селектор «сотрудник» — выпадающий список |
| `search` | поиск по ФИО | поле ввода в шапке самого чарта (Controls) |

Фильтрация выполняется на вкладке Prepare, **до** построения дерева: отсекаются
строки, потом собираются ветки. Поэтому при выборе одного руководителя
остаётся ровно его ветка, а числа в узлах выше пересчитываются под неё.

## Часть 5. Вкладка Sources

Запрос к датасету. Алиас `hrTree` берётся из Meta через `Editor.getId`.

Файл: [`editor/structure-tree.sources.js`](editor/structure-tree.sources.js)

```js
function field(title) {
    return { ref: { type: 'title', title: title } };
}

module.exports = {
    tree: {
        datasetId: Editor.getId('hrTree'),
        data: {
            fields: [
                field('Блок'),
                field('Проект'),
                field('Руководитель'),
                field('Продукт кратко'),
                field('риск'),
                field('R4'),
                field('R3'),
                field('R2'),
                field('R1'),
                field('R0'),
                field('людей'),
                field('вакансий'),
                field('ФОТ_мес'),
                field('заместитель'),
                field('команда'),
                field('Сотрудник')
            ]
        }
    }
};
```

Это канонический формат из документации. Короткая запись через
`require('libs/dataset/v2')` делает то же самое, но зависит от версии
служебного модуля, которого в части инсталляций нет; она оставлена
в файле закомментированной.

**Главная ловушка здесь.** Значения `title` должны совпадать с названиями
полей в датасете **побуквенно, включая регистр**:

```
людей      — не «Людей»
вакансий   — не «Вакансий»
риск       — не «Риск»
ФОТ_мес    — с подчёркиванием, не «ФОТ мес»
```

Если хоть одно не совпадёт, источник вернёт пустой результат **без ошибки**.
Именно из-за этого чарт может нарисовать одну легенду и ничего больше.
Сверьте названия, открыв датасет.

Порядок полей задаёт порядок колонок в ответе и продублирован константой
`COLUMNS` на вкладке Prepare.

## Часть 6. Вкладка Prepare

Основной код. Открыть
[`editor/structure-tree.prepare.js`](editor/structure-tree.prepare.js),
скопировать **целиком**, вставить.

Файл заканчивается так — это и есть обязательная структура Advanced-чарта:

```js
module.exports = {
    render: Editor.wrapFn({
        fn: function (options, scene) {
            // ...собираем SVG-строку из scene...
            return Editor.generateHtml('<div style="…">' + svg + '</div>');
        },
        args: [scene]
    })
};
```

Первым аргументом `fn` всегда приходят размеры виджета: `options.width`
и `options.height`. Дерево оборачивается в `div` с `overflow:auto` ровно
этого размера — иначе DataLens обрежет полотно по ячейке дашборда, а не
прокрутит его.

Настройки вынесены в начало файла:

```js
var ROW       = 34;                          // высота строки
var NODE_H    = 30;                          // высота узла
var STRIP     = 5;                           // толщина полосы состава
var GAP       = 16;                          // зазор между колонками
var COL_RATIO = [0.20, 0.21, 0.20, 0.39];    // доли ширины по уровням
var MIN_WIDTH = 900;                         // ниже — горизонтальная прокрутка
```

**Ширина резиновая.** Колонки заданы долями, а не пикселями, поэтому дерево
растягивается на всю ширину виджета: на широком экране названия продуктов
перестают обрезаться, на узком включается горизонтальная прокрутка.
Пиксельные координаты считаются на клиенте — только там известен фактический
размер, и по этой же причине подрезка длинных названий тоже выполняется там.

Сумма `COL_RATIO` должна равняться 1. Хотите отдать больше места продуктам —
увеличьте последнюю долю и уменьшите остальные.

Высота растёт от числа строк: 58 карточек дают около 2020 px. Виджет ниже
этого — дерево прокручивается внутри себя, подгонять высоту не нужно.

## Часть 7. Вкладка Controls — быстрый поиск по ФИО

Основной способ выбрать человека — **выпадающий селектор «Сотрудник»** на
дашборде, он описан в [части 9](#селекторы). Эта вкладка добавляет к нему
второй, необязательный способ: поле ввода в шапке самого чарта, где можно
набрать кусок фамилии, не открывая список из 180 значений.

Элементы управления с этой вкладки живут отдельно от селекторов дашборда:
рисуются в шапке виджета, влияют только на этот чарт и сбрасываются при
перезагрузке страницы.

Если поле ввода не нужно — оставьте на вкладке `module.exports = {};`,
селектор от этого не пострадает.

Файл: [`editor/structure-tree.controls.js`](editor/structure-tree.controls.js)

```js
module.exports = {
    controls: [
        {
            type: 'input',
            param: 'search',
            label: 'Поиск сотрудника',
            labelPlacement: 'left',
            placeholder: 'фамилия или табельный номер',
            width: 260,
            updateOnChange: true
        }
    ]
};
```

Формат вкладки — объект с массивом `controls`. Обязательные поля контрола:
`type` и `param`. `updateOnChange: true` перерисовывает чарт сразу после
ввода; без него значение запишется в параметр, а дерево останется прежним.

**Параметр `search` обязан быть объявлен на вкладке Params** — иначе
значение до чарта не дойдёт.

### Как работает поиск

Введённый текст уходит в параметр `search`, вкладка Prepare читает его
через `Editor.getParams()` и оставляет только те продукты, где этот человек
есть. Ищем в трёх местах, а не только в составе команд:

| Где | Что это значит на карточке |
|---|---|
| колонка `команда` | человек в составе продукта |
| колонка `Руководитель` | он руководитель продукта |
| колонка `заместитель` | он заместитель руководителя |

Правила совпадения:

- **регистр и «ё» не важны**: `трошина`, `Трошина`, `ТРОШИНА` — одно и то же;
- **фамилия ищется по куску**: `Трош` найдёт «Трошина Е.Н.»;
- **чисто цифровой запрос ищется целиком**. Пока сотрудники обезличены
  табельными номерами, поиск по вхождению вёл бы себя плохо: `11` цеплял бы
  110…119. Запрос `1` находит ровно сотрудника 1. Когда в выгрузке появятся
  настоящие ФИО, правило само перестанет срабатывать — оно только для цифр.

Что показывается в результате:

```
поиск «68»:  68 — Руководитель проекта  ·  8 продуктов  ·  1 направление
```

Дерево сворачивается до веток, где человек есть, — сразу видно, на скольких
продуктах он занят и под кем. Числа в узлах пересчитываются под этот срез,
поэтому рядом видно и полный состав команд, в которых он работает. Если
открыть карточку продукта, найденный человек в списке команды подсвечен.

Поиск работает **внутри** остальных селекторов: если стоит фильтр по
направлению, а человек в другом — ничего не найдётся. Об этом написано
прямо в сообщении «Никого не нашли».

Если контролы в вашей инсталляции не отображаются, тот же параметр можно
завести селектором дашборда типа «Ручной ввод» с параметром `search` —
чарт принимает и это имя, и `поиск`.

**Поиск и селектор — разные механизмы.** Селектор ищет точным совпадением
по колонке `Сотрудник`, поле ввода — по куску строки в составе команд,
руководителях и заместителях. Работают вместе: можно выбрать человека
в списке, а полем сузить дальше.

## Часть 7б. Заместитель и состав команды

Две вещи, которые появляются автоматически, если в выгрузке есть колонки
`заместитель` и `команда`.

### Заместитель руководителя

Заполняется вручную в исходном файле — добавьте столбец **«Заместитель»**
рядом с «Непосредственный руководитель». Скрипт подхватит его сам: столбец
описан как необязательный, без него ничего не сломается.

Значение берётся первое непустое по ветке руководителя — заместитель
относится к человеку, а не к отдельному продукту, поэтому заполнять его
в каждой строке не нужно.

В дереве он выводится серым рядом с фамилией:

```
Килигин Ю.С.    зам. Смирнов А.А.              42 чел
```

Если места между фамилией и счётчиком мало, подпись подрезается; при
совсем узкой колонке — не показывается вовсе.

### Состав команды по клику

**Клик по продукту разворачивает панель с его командой.** Закрыть можно
двумя способами: крестиком в правом верхнем углу панели или повторным
кликом по самому продукту.

Крестик нужен не для удобства, а по необходимости: когда дерево
отфильтровано до одного продукта, панель перекрывает его карточку,
и кликнуть по продукту повторно уже нечем.

Что в панели:

- **шапка** — название продукта, численность, вакансии и ФОТ;
- **список** — фамилия и проектная роль, от старших ролей к младшим;
- **точка слева** окрашена в цвет уровня роли, тот же, что в полосе
  состава на узле, — глазу не нужно переводить между двумя кодировками;
- строки через одну подложены светлым, чтобы длинный список читался.

Панель ложится поверх узлов ниже и **не сдвигает раскладку** — дерево
не «прыгает» при каждом клике. Если снизу не помещается, раскрывается
вверх.

Данные берутся из колонки `команда` — готовой строки вида
`68 — Руководитель проекта; 22 — Руководитель продукта; …`, собранной
скриптом. Второй источник не нужен: всё приходит одним запросом.

Технически: элементы карточки продукта помечены атрибутом `data-id`,
обработчик `events.click` кладёт этот id в состояние чарта через
`Chart.setState`, что вызывает повторный `render` с панелью. Атрибут висит
на всех элементах карточки — на рамке, названии, числах и полосе состава, —
поэтому клик срабатывает в любой её точке. У крестика свой `data-id="close"`.

### Подсветки риска в дереве нет

Раньше продукты с одним-двумя людьми обводились красным и жёлтым. Убрано:
цвет мешал читать состав, а сам риск никуда не делся — он считается
в колонке `риск` на листе «Иерархия» и разбирается отдельным чартом
(C7.3 в [`08-hierarchy-tab.md`](08-hierarchy-tab.md)).

### Строка итогов среза

Вторая строка сверху, пересчитывается при каждом изменении фильтров:

```
в срезе:  4 направл. · 12 проект. · 18 руковод. · 58 продукт.
          · 180 сотрудников · 31,69 млн ₽ · +35 вакансий
```

**Сотрудники считаются уникальными — и в строке итогов, и на узлах.**
Колонка `людей` приходит по продуктам. Складывать её вверх по дереву
нельзя: человек, занятый на двух продуктах, дал бы двойку и на
руководителе, и на проекте, и на направлении — так у Ульянова А.Ю.
получалось 81 человек вместо 66, у Богдановой Н.С. 45 вместо 32, а по
всему срезу 217 вместо 180.

Поэтому на каждом узле выше продукта чарт заново собирает состав по
фамилиям из колонки `команда` и считает уникальных. Полоса состава и
бейдж `R4-R3-R2-R1-R0` пересчитываются там же, поэтому пять чисел всегда
складываются в число слева от них. Если человек на разных продуктах
числится в разных ролях, он попадает в сегмент старшей.

Пересчёт включается, только если состав читается целиком: у каждого
участника распознана роль и число фамилий совпадает с колонкой `людей`.
Иначе чарт молча остаётся на суммах — они завышают численность, но
никого не теряют. Без колонки `команда` в строке итогов будет написано
«назначений», а не «сотрудников».

ФОТ суммировать можно как есть, и он суммируется: зарплата уже разнесена
по назначениям в копейках, двойного счёта нет. Вакансии тоже — это
позиции, а не люди.

**Продукты без единого человека в дереве есть.** Скелет строится по всем
строкам выгрузки, а не только по людям: продукт, на котором пока никого
нет, существует, и набор на него надо к чему-то привязать. Такая карточка
помечена «команды нет +N вак», не раскрывается по клику и не даёт полосы
состава. Сейчас такой один — «Регистрация блоггеров» у Горбуновой А.В.

Поэтому вакансий в строке итогов ровно 35 — столько же, сколько
в выгрузке. Раньше их было 34: продукт без людей в дерево не попадал,
и одна открытая позиция пропадала из виду.

### ФОТ на узлах

### Селекторы

Пять штук: ответственный за направление, направление, руководитель
продукта, продукт и **сотрудник**.

#### Создать

Для каждого селектора:

1. Дашборд → **Редактировать**.
2. На панели внизу зажать **Селектор** и перетащить в шапку вкладки.
3. Вкладка **Селекторы**, источник — **На основе датасета**.
4. Заполнить:

| Настройка | Значение |
|---|---|
| **Датасет** | `HR · Иерархия` |
| **Поле** | см. таблицу ниже |
| **Тип селектора** | Список |
| **Операция** | **оставить пустой** |
| **Множественный выбор** | включить |
| **Заголовок** | см. таблицу ниже |

| Заголовок селектора | Поле датасета |
|---|---|
| Ответственный за направление | `Блок` |
| Направление | `Проект` |
| Руководитель продукта | `Руководитель` |
| Продукт | `Продукт кратко` |
| Сотрудник | `Сотрудник` |

Для селектора **Сотрудник** дополнительно включите **Поиск по значениям**:
в списке 180 фамилий, без поиска в нём неудобно.

**Операцию оставляйте пустой** — это прямо оговорено в документации: её не
указывают, когда селектор связан с параметрами чарта. С заполненной
операцией значение приедет в чарт в виде `__gte_Транспорт` и ни с чем не
совпадёт.

Пять селекторов удобно сложить в один виджет **группы селекторов** — тогда
они встанут в одну строку и не растащат шапку.

#### Связать с деревом

Селекторы и чарты на одном датасете DataLens связывает сам, а датасет
у дерева объявлен на вкладке Meta — поэтому обычно достаточно проверить:

1. Вкладка → **Связи** (иконка цепочки справа вверху).
2. Убедиться, что между каждым селектором и чартом `Структура работ`
   стоит **Исходящая** связь (селектор влияет на чарт).

Если связи нет или она помечена «Не связаны» — поставьте **Исходящую**
вручную.

#### Селектор «Сотрудник»: что для него нужно в датасете

Выпадающий список берёт значения из колонки датасета. Колонки с одним
человеком в строке в выгрузке раньше не было: состав лежал строкой в
`команда`, а строка была одна на продукт. Поэтому лист «Иерархия» теперь
разворачивается по людям — **одна строка на пару «продукт — сотрудник»**,
218 строк вместо 58, плюс колонка `Сотрудник`.

Показатели продукта (`людей`, `R4…R0`, `ФОТ_мес`, `команда`) повторяются
на каждой строке продукта. Чарт схлопывает строки обратно по ключу
«Блок · Проект · Руководитель · Продукт кратко», поэтому в дереве ничего
не задваивается — 218 строк дают те же 92 узла и те же 180 человек.

> В Excel по листу «Иерархия» нельзя суммировать `ФОТ_мес` напрямую —
> получится завышение в разы. Для сумм есть лист «Проекты».

Что сделать один раз:

1. Перегенерировать выгрузку: `python3 prepare_dataset.py`.
2. Залить новый файл в то же подключение DataLens.
3. Датасет → **Обновить поля**. Появится поле `Сотрудник`.
4. В чарте на вкладке **Sources** добавить `field('Сотрудник')` последним
   в списке, на вкладке **Params** — `employee: []` и `'Сотрудник': []`.
   Оба уже есть в готовых файлах.
5. Нажать **Выполнить**, сохранить чарт.

Поле обязано быть в Sources, даже если в дереве оно не рисуется: чарт
узнаёт ID поля из ответа источника, а без запроса поля ID не придёт и
селектор не свяжется.

**Если перезаливать файл сейчас не хочется**, есть обходной путь без
изменений в датасете: селектор с источником **«Ручной ввод»**, тип
«Список», параметр `employee`, значения — из файла
`datalens_dataset_employees.txt`, который скрипт кладёт рядом с выгрузкой
(180 строк, по одной фамилии). Работает сразу, но список не обновляется
сам: при изменении состава его придётся вставить заново.

#### Проверка

Выберите одного руководителя. Должно произойти три вещи:

- в дереве останется одна ветка;
- в строке легенды появится «фильтр — руководитель: …»;
- числа в узлах направления и проекта пересчитаются под эту ветку
  (у Ульянова А.Ю. станет 42 человека вместо 81).

#### Как чарт узнаёт значение селектора

Селектор на основе датасета передаёт значение параметра **под ID поля**, а не
под его названием — это прямо сказано в документации по параметрам дашборда.
ID выглядит как `f7a1c3e2-…`, вручную его нигде не задают.

Чарт разбирается сам: он берёт из ответа источника карту «название поля → ID»
и принимает значение под любым из трёх имён:

```
block            латинское имя со вкладки Params
Блок             название поля датасета
f7a1c3e2-…       ID поля — то, что реально шлёт селектор на датасете
```

Плюс снимаются префиксы операций: `__in_Транспорт` и `__eq_Транспорт`
понимаются как `Транспорт`.

#### Если не фильтрует

Чарт скажет, что не так, второй строкой в шапке:

```
⚠ параметр пришёл, но фильтра под него нет: zzz — добавьте это имя
  в FILTERS и Params
```

Значит значение доезжает, но под неожиданным именем. Впишите его в два места:

```js
// Params
'zzz': [],

// Prepare, массив FILTERS
{ keys: ['product', 'Продукт кратко', 'zzz'], column: 'Продукт кратко',
  label: 'продукт' },
```

**Строки-предупреждения нет вообще, и ничего не фильтруется** — значит
параметр до чарта не доезжает. Включите в начале Prepare отладку:

```js
var DEBUG_PARAMS = true;
```

Тогда во второй строке шапки появится всё, что пришло:

```
параметры: f7a1c3e2-… = Килигин Ю.С.   ·   tab = Структура
```

Если строка говорит «ни одного параметра не пришло» — дело в связи,
а не в имени:

1. Вкладка → **Связи**, между селектором и чартом `Структура работ`
   должна стоять **Исходящая**.
2. В настройках селектора **Операция** должна быть пустой.
3. Селектор и чарт должны быть на одной вкладке дашборда.
4. Проверьте, что в Meta указан id именно того датасета, на котором
   построен селектор.

После починки верните `DEBUG_PARAMS = false`.

**Запасной вариант**, если связь по датасету упорно не работает: селектор
типа **Ручной ввод**, поле **Поле или параметр** = `block`, `project`,
`chief` или `product`. Имя параметра задаётся явно, разночтений нет, но
значения списка придётся вписать руками — для продуктов это 57 строк,
поэтому вариант последний.

## Часть 10. Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| «Не удалось получить id» на Sources | алиас не описан в Meta или опечатка | сверить ключ в Meta и в `Editor.getId()` |
| Пусто, ошибок нет | так больше не бывает: чарт покажет панель с причиной | читать панель |
| «Нет колонки «ФОТ_мес». Пришли: …» | колонка не запрошена в Sources или переименована в датасете | добавить в `columns`, проверить название в датасете |
| Отрисовалась только легенда | старая версия кода | обновить Prepare: теперь вместо легенды рисуется панель с причиной |
| Дерево обрывается на середине | сработал лимит строк | добавить в `buildSource` параметр `limit: 1000` |
| Превышено время выполнения Prepare | 10 секунд на вкладку | уменьшить число строк в источнике |
| Разметка отрисовалась текстом | забыт `Editor.generateHtml` | вернуть строку через него — без обёртки всё экранируется |
| Название налезает на числа справа | длинные названия продуктов | увеличить `NODE_W[3]` или `TITLE_CH` |
| Поля поиска в шапке чарта нет | вкладка Controls не сохранена или контролы не поддерживаются инсталляцией | нажать «Выполнить» и сохранить; если не появилось — завести селектор дашборда «Ручной ввод» на параметр `search` |
| Поиск не фильтрует, поле работает | параметр `search` не объявлен на Params | добавить `search: ['']` в Params |
| «Никого не нашли» на заведомо существующем человеке | поиск идёт внутри среза остальных селекторов | снять фильтры по направлению и продукту |

**Чарт диагностирует себя сам.** Если данных нет, не хватает колонки или
значения не читаются, вместо дерева рисуется панель «Дерево не построено» —
с причиной, журналом разбора и списком того, что проверить.

Журнал показывает, например:

```
Ключи источников: tree
Ключи внутри «tree»: notifications, data_export_forbidden, result_data, fields, …
Формат: result_data[0].rows, строк — 57
Строка — объект data + legend, значений: 13
Колонки: Блок · Проект · Руководитель · Продукт кратко · риск · R4 · …
Первая строка: Ульянов А.Ю. · Забота и сопровождение · Бирюкова В.В. · …
```

Шесть строк отвечают на всё: дошёл ли запрос, в каком формате ответ,
сколько строк, как устроена строка, как называются колонки и что в них
лежит на самом деле.

Разбор умеет четыре вида строки и определяет их сам:

| Вид строки | Где встречается |
|---|---|
| `[значение, ...]` | ответ через `result.data.Data` |
| `{values: [...]}` | старый формат |
| `{data: [...], legend: [...]}` | текущий формат DataLens |
| `{Блок: '…', Проект: '…'}` | объект с ключами-названиями |

Отдельно сверяется число колонок с числом значений в строке: `fields`
в ответе может описывать весь датасет, а не только запрошенные поля,
и тогда имена не совпали бы со значениями по позиции. В этом случае
берётся порядок, объявленный в `COLUMNS`.

## Что этот чарт не умеет

- **Тултипов нет.** Клик по продукту раскрывает состав команды, но
  наведение мышью ничего не показывает. Тултипы в Advanced-чарте возможны —
  через тег `dl-tooltip` или блок `tooltip` рядом с `render`, — но здесь
  не заводились.
- **Поиск не сохраняется.** Контролы вкладки Controls живут только до
  перезагрузки страницы: обновили дашборд — поле пустое, дерево целиком.
  Ссылку «на этого сотрудника» так не дать; для этого поиск нужно вынести
  в селектор дашборда, тогда значение попадёт в URL.
- **Тёмная тема не поддерживается**: цвета заданы явно в `THEME`. При
  желании их можно перевести на CSS-переменные с префиксом `--ce-theme`,
  которые DataLens подставляет под текущую схему.
- **Переименование поля в датасете ломает чарт.** Он покажет понятную
  ошибку со списком пришедших колонок, но чинить придётся в коде.
- **Это дерево структуры работ, а не подчинённости.** Дерево «кто кому
  подчиняется» строится тем же кодом, но требует столбца `ID руководителя`
  в той же нумерации, что и `ФИО (штат)`.

## При обновлении данных

Код трогать не нужно: замените файл в подключении `hr_tree`, чарт
перечитает датасет сам, высота полотна пересчитается. Правка нужна только
при изменении состава столбцов — тогда синхронно меняются `columns`
на Sources и `COLUMNS` на Prepare.
