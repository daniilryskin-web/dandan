# 06. Полная инструкция по сборке дашборда в DataLens

Документ описывает дашборд **под конкретный датасет**, который выдаёт `prepare_dataset.py`. Это рабочая инструкция: открываете её рядом с DataLens и собираете сверху вниз.

Файл `03-charts.md` писался по описанию таблицы и местами устарел. **Где они расходятся, верен этот файл.**

---

## Часть 0. Подготовка

### 0.1. Получить датасет

```bash
python3 prepare_dataset.py "занятость.xlsx" \
    --sheet "Поправлено (Как будет)" \
    --out datalens_dataset \
    --snapshot 2026-08-01
```

Скрипт печатает 17 проверок, контроль монотонности по уровням ролей и по грейдам, и сводку по типам отклонений. **Пока не увидели «Монотонность: ОК» в обеих строках — дальше не идите:** это значит, что классификация нарушена и сравнивать зарплаты не с чем.

На выходе `datalens_dataset.csv` — его и грузим.

### 0.2. Подключение и датасет

1. **Подключения → создать → Файлы** → загрузить `datalens_dataset.csv`. Кодировка UTF‑8, разделитель — запятая, первая строка — заголовки.
2. **Датасеты → создать** → выбрать подключение → добавить таблицу.
3. Проверить типы полей. DataLens определяет их сам, но три места стоит посмотреть:

| Поле | Должно быть | Почему это важно |
|---|---|---|
| `Сотрудник` | Строка | Иначе идентификаторы поедут как «176.0» на всех подписях |
| `Дата среза` | Дата | Понадобится, когда накопятся месячные срезы |
| `Грейд №`, `Уровень роли №`, `Вакансия`, `Первичное назначение`, `ЗП подтверждена`, `В анализе справедливости`, `Требует внимания` | Целое | Это флаги и порядковые номера, по ним считаются суммы и сортировки |

### 0.3. Форматы отображения

Настраивается в свойствах поля. Сделать один раз — иначе чарты будут пестрить числами вида `31692786.0`.

| Поля | Формат |
|---|---|
| `ЗП`, `ФОТ аллоцированный`, `База сравнения`, `Отклонение руб`, `Доплата до порога`, `Оценка стоимости вакансии`, `Разрыв должность − роль, руб`, все медианы и квартили | Число, разделитель разрядов, 0 знаков, префикс «₽» |
| `Compa-ratio`, `Compa-ratio к должности` | Число, 2 знака |
| `Доля занятости` | Число, 2 знака |
| `Z-score` | Число, 2 знака |

### 0.4. Иерархия для drill-down

Датасет → **Поля → создать иерархию**:

```
Организационная:  Блок → Проект → Продукт → Проектная роль → Сотрудник
```

Клик по столбцу блока проваливает в его проекты, дальше в продукты. Это заменяет три селектора и сильно упрощает вкладку 0.

## Часть 1. Вычисляемые поля в датасете

Большая часть расчётов уже сделана скриптом. В DataLens добавляем только то, что зависит от параметров и от разреза чарта.

### 1.1. Параметры

Датасет → вкладка **«Параметры»**.

| Параметр | Тип | По умолчанию | Назначение |
|---|---|---|---|
| `p_Взносы` | Дробное | `0.302` | Страховые взносы. Для аккредитованных IT — `0.076` |
| `p_Накладные` | Целое | `15000` | Рабочее место, техника, ДМС на человека в месяц |
| `p_Индексация` | Целое | `10` | % повышения для what-if сценария |

Параметры выводятся на дашборд селекторами типа «Ввод». Пользователь крутит их сам и видит, как меняются цифры — это сильно повышает доверие к дашборду.

### 1.2. Поля

Создаются на вкладке **«Поля»**. Порядок важен: поля ссылаются на предыдущие.

**Численность и объём**

```
Сотрудников          = COUNTD([Сотрудник]) - COUNTD(IF [Вакансия] = 1 THEN [Сотрудник] END)
```
Проще и надёжнее — через флаг первичного назначения:
```
Сотрудников          = SUM([Первичное назначение])
Открытых вакансий    = SUM([Вакансия])
Назначений           = COUNT([Строка])
FTE                  = SUM(IF [Вакансия] = 0 THEN [Доля занятости] ELSE 0 END)
FTE вакансий         = SUM(IF [Вакансия] = 1 THEN [Доля занятости] ELSE 0 END)
Продуктов            = COUNTD([Продукт ключ])
Проектов             = COUNTD([Проект])
```

> **Почему `SUM([Первичное назначение])`, а не `COUNTD([Сотрудник])`.** Оба верны, но первое считается быстрее и переживает любые разрезы. Единственная тонкость: если в чарте стоит фильтр по проекту, «первичной» может оказаться строка из другого проекта, и человек не посчитается. Поэтому: **на вкладке 0 (общие итоги) — `SUM([Первичное назначение])`, на вкладках с фильтром по проекту — `COUNTD([Сотрудник])`.** Оба поля заведите сразу, назовите `Сотрудников (всего)` и `Сотрудников (в срезе)`.

**Деньги**

```
ФОТ, мес             = SUM([ФОТ аллоцированный])
ФОТ, год             = [ФОТ, мес] * 12
Полная стоимость мес = [ФОТ, мес] * (1 + [p_Взносы]) + [p_Накладные] * [FTE]
Полная стоимость год = [Полная стоимость мес] * 12
Стоимость FTE        = [ФОТ, мес] / [FTE]
Средняя ЗП           = SUM(IF [Первичное назначение] = 1 THEN [ЗП] ELSE 0 END)
                       / SUM([Первичное назначение])
Медианная ЗП         = MEDIAN(IF [Первичное назначение] = 1 THEN [ЗП] END)
Разрыв среднее/медиана = [Средняя ЗП] / [Медианная ЗП]
Доля ФОТ от общего   = [ФОТ, мес] / SUM([ФОТ аллоцированный] TOTAL)
```

**Вакансии**

```
Стоимость вакансий мес = SUM([Оценка стоимости вакансии])
Стоимость вакансий год = [Стоимость вакансий мес] * 12
Прирост ФОТ при найме  = [Стоимость вакансий мес] / [ФОТ, мес]
```

**Справедливость оплаты**

База сравнения — медиана по **проектной роли**, то есть по фактически выполняемой работе. Штатная должность в базу не входит: её могли назначить формально, чтобы обосновать оклад (обоснование — `05-adaptation.md`, §3.5). Грейд используется как диагностика через `Compa-ratio к должности`.

```
Людей в анализе      = SUM([В анализе справедливости])
Людей на ревью       = SUM([Требует внимания])
Людей на ревью (подтв.) = SUM(IF [ЗП подтверждена] = 1 THEN [Требует внимания] ELSE 0 END)

Оплата по должности  = SUM(IF [Тип отклонения] = '2. Оплата по должности, а не по роли'
                             THEN 1 ELSE 0 END)
Роль выше должности  = SUM(IF [Тип отклонения] = '4. Роль выше должности' THEN 1 ELSE 0 END)
Переплата за роль, год = SUM(IF LEFT([Тип отклонения], 1) IN ('2', '3')
                               THEN [Отклонение руб] ELSE 0 END) * 12

Выравнивание, мес       = SUM([Доплата до порога])
Выравнивание, год       = [Выравнивание, мес] * 12
Выравнивание с взносами = [Выравнивание, год] * (1 + [p_Взносы])
Прирост ФОТ от выравнивания = [Выравнивание, мес] / [ФОТ, мес]

Выравнивание подтв., год = SUM(IF [ЗП подтверждена] = 1 THEN [Доплата до порога] ELSE 0 END) * 12
```

**What-if индексация**

```
ФОТ после индексации = SUM(
  IF [Требует внимания] = 1 AND [Compa-ratio] < 1
  THEN [ФОТ аллоцированный] * (1 + [p_Индексация] / 100)
  ELSE [ФОТ аллоцированный] END
)
Стоимость сценария   = [ФОТ после индексации] - [ФОТ, мес]
```

**Качество данных**

```
Доля подтверждённых ЗП = SUM(IF [Первичное назначение] = 1 THEN [ЗП подтверждена] ELSE 0 END)
                         / SUM([Первичное назначение])
Продуктов с 1 человеком = COUNTD(IF [Bus factor] = 'Критично: 1 человек' THEN [Продукт ключ] END)
```

**Оформление**

```
Бейдж ЗП = CASE [Флаг ЗП]
  WHEN '1. Недоплата'   THEN COLOR(BOLD('▼▼ Недоплата'),  '#b3261e')
  WHEN '2. Ниже группы' THEN COLOR('▼ Ниже группы',       '#b3261e')
  WHEN '3. Норма'       THEN COLOR('● Норма',             '#52514e')
  WHEN '4. Выше группы' THEN COLOR('▲ Выше группы',       '#184f95')
  WHEN '5. Переплата'   THEN COLOR(BOLD('▲▲ Переплата'),  '#184f95')
  ELSE COLOR('— не сравнивается', '#898781') END

Бейдж причины = CASE [Тип отклонения]
  WHEN '2. Оплата по должности, а не по роли' THEN COLOR(BOLD('▲ Должность выше роли'), '#184f95')
  WHEN '3. Выше и роли, и должности'          THEN COLOR('▲ Выше всего',                '#184f95')
  WHEN '4. Роль выше должности'               THEN COLOR(BOLD('▼ Роль выше должности'), '#b3261e')
  WHEN '5. Недоплата за роль'                 THEN COLOR('▼ Недоплата за роль',         '#b3261e')
  WHEN '1. Норма'                             THEN COLOR('● Норма',                     '#52514e')
  ELSE COLOR('—', '#898781') END

Метка достоверности = IF [ЗП подтверждена] = 0
  THEN COLOR('⚠ ЗП не подтверждена', '#b3261e') ELSE '' END

Корзина ЗП = FLOOR([ЗП] / 50000) * 50000
```

## Часть 2. Палитры

Создаются в настройках воркбука (**Палитры → создать**). Три штуки.

**«Категориальная»** — для идентичности: блоки, организации, проектные роли.
```
#2a78d6  #eb6834  #1baf7a  #eda100  #e87ba4  #008300  #4a3aa7  #e34948
```
Проверено на различимость при дальтонизме. Максимум 8 значений; на точечных диаграммах безопасны первые три.

**«Светофор ЗП»** — для флага отклонения, ровно три цвета:
```
Недоплата #b3261e   Норма #a8a7a0   Переплата #184f95
```
Привязывается к полю `Цвет флага` (не к `Флаг ЗП` — там пять значений).

**«Грейды»** — порядковая шкала, один синий тон светлый → тёмный:
```
#cde2fb  #9ec5f4  #6da7ec  #3987e5  #2a78d6  #256abf  #184f95
```
Привязывается к `Грейд`. Грейд — это упорядоченная шкала, красить её категориальными цветами нельзя.

### Правило, которое здесь легче всего нарушить

**Не раскрашивайте 12 проектов в 12 цветов.** Надёжно различимых категориальных цветов максимум восемь. Столбики проектов делаются **одним** цветом — их длина уже кодирует величину. Нужен акцент — подсветите один проект, остальные серым `#c3c2b7`. Нужны разные цвета — красьте по блоку (4 значения), грейду (7, порядковой шкалой) или флагу ЗП (3).

# Вкладка 0 — Обзор

**Вопрос:** сколько всё это стоит и где перекосы.

**Селекторы:** `Блок` · `Организация` · `Грейд`

### KPI-ряд (тип чарта «Индикатор»)

| № | Плитка | Поле | Ожидаемое значение |
|---|---|---|---|
| 1 | Сотрудников | `Сотрудников (всего)` | 180 |
| 2 | Открытых вакансий | `Открытых вакансий` | 35 |
| 3 | ФОТ, мес | `ФОТ, мес` | 31.7 млн ₽ |
| 4 | Полная стоимость, год | `Полная стоимость год` | ≈ 528 млн ₽ |
| 5 | Средняя / медианная ЗП | два индикатора рядом | 176 / 135 тыс ₽ |
| 6 | FTE | `FTE` | 180 |
| 7 | Стоимость вакансий, год | `Стоимость вакансий год` | 70 млн ₽ |
| 8 | Доля подтверждённых ЗП | `Доля подтверждённых ЗП` | 68% |

Плитка 4 обычно удивляет сильнее всех: полная стоимость на треть выше того, что видно в столбце зарплат. Плитка 7 отвечает на вопрос, который в таблице не задан вовсе — «во сколько обойдётся закрыть набор» (+18% к ФОТ). Плитка 8 — индикатор доверия ко всему остальному.

### C0.1 — ФОТ по проектам

- **Тип:** Линейчатая (горизонтальные полосы). Названия проектов длинные, на вертикальных столбцах лягут по диагонали.
- **Y:** `Проект` · **X:** `ФОТ, мес` · **Сортировка:** X по убыванию
- **Цвет:** один, слот 1
- **Подписи:** значение
- **Зачем.** Первое, что видит открывший дашборд. Порядок направлений по стоимости почти всегда расходится с интуитивным представлением. Численность сюда **не добавляйте второй осью** — двух осей Y на чарте быть не должно, соотношение шкал произвольно и чарт начинает «показывать» корреляцию, которой нет.

### C0.2 — Стоимость полной ставки по проектам

- **Тип:** Линейчатая, **тот же порядок проектов, что в C0.1** — глаз сравнивает два чарта построчно
- **Y:** `Проект` · **X:** `Стоимость FTE`
- **Референсная линия:** среднее по компании (≈ 176 тыс)
- **Зачем.** Отвечает на вопрос, который C0.1 не отвечает: проект дорогой потому, что людей много, или потому что люди дорогие. На ваших данных разброс от 124 до 246 тыс — двукратный, и он отражает разный состав грейдов, а не разные ставки.

### C0.3 — Древовидная карта «Проект → Продукт»

- **Тип:** Древовидная (Treemap)
- **Разбивка:** `Проект`, затем `Продукт` · **Размер:** `ФОТ, мес` · **Цвет:** `Стоимость FTE`, палитра «Грейды» как последовательная
- **Зачем.** Единственный чарт, где одновременно видны структура (что во что вложено), вес (сколько стоит) и качество (насколько дорогая команда). Крупная тёмная плитка — дорогой продукт с дорогой командой, первый кандидат на разбор.
- **Нюанс.** 71 продукт — многовато для одного экрана. Ограничьте до уровня проектов, а продукты открывайте через drill-down.

### C0.4 — Структура ФОТ по грейдам

- **Тип:** Столбчатая с накоплением, нормированная на 100%. Одна полоса на весь экран, разбитая на сегменты
- **Разбивка:** `Грейд` · **Значение:** `ФОТ, мес` · **Цвет:** палитра «Грейды»
- **Сортировка:** по `Грейд №`
- **Зачем.** Соотношение уровней в деньгах. На ваших данных G5 и выше съедают почти половину ФОТ при четверти численности.
- **Нюанс.** Между сегментами — зазор 2 px цветом фона, не обводка. Подпись внутри сегмента только если помещается целиком, иначе выносится наружу.

### C0.5 — Матрица «Грейд × Проект»

- **Тип:** Сводная таблица с тепловой заливкой
- **Строки:** `Грейд` (сортировка по `Грейд №`) · **Столбцы:** `Проект` · **Значение:** `Сотрудников (в срезе)` · **Заливка:** последовательная синяя
- **Итоги:** включить по строкам и столбцам
- **Зачем.** Структура штата — на мой взгляд, самая содержательная картинка во всём дашборде. Сразу видно, что доля начальных грейдов по проектам гуляет от 0% до 68%: часть направлений укомплектована дорогими позициями целиком, часть держится на стажёрах и специалистах. Это разговор не про зарплаты, а про то, как устроены команды.
- **Второй экземпляр** того же чарта со значением `ФОТ, мес` — та же матрица в деньгах.

### C0.6 — Распределение зарплат

- **Тип:** Столбчатая (гистограмма). DataLens не строит гистограммы сам, поэтому нужен разрез `Корзина ЗП`
- **X:** `Корзина ЗП` · **Y:** `Сотрудников (в срезе)` · **Фильтр:** `Первичное назначение` = 1
- **Референсные линии:** медиана и среднее
- **Зачем.** Форма распределения говорит больше, чем среднее. На ваших данных распределение многогорбое — это прямое следствие тарифной сетки: масса людей стоит ровно на ступенях 31/72/120/250/350 тыс. Средняя по такому распределению почти бессмысленна, и чарт это показывает наглядно.

### C0.7 — Вакансии

- **Тип:** Линейчатая
- **Y:** `Проектная роль` · **X:** `Открытых вакансий` · **Фильтр:** `Вакансия` = 1
- **Подписи:** количество и `Стоимость вакансий мес`
- **Зачем.** Две трети открытых позиций приходятся на две роли — это показывает, где идёт активный набор, и одновременно даёт прогноз прироста ФОТ.

# Вкладка 1 — Проекты и продукты

**Вопрос:** покажи направление целиком.

**Селекторы:** `Проект` (одиночный выбор, обязательный) · `Продукт` · `Грейд`

### Карточка направления

Текстовый виджет + KPI: `Сотрудников (в срезе)` · `FTE` · `ФОТ, мес` · `Стоимость FTE` · `Открытых вакансий` · `Продуктов`.

В текстовом виджете — блок, ответственный и список руководителей. Списки собираются полем:
```
Руководители проекта = ALL_CONCAT([Руководитель], ', ')
```

### C1.1 — Состав команды

- **Тип:** Линейчатая с накоплением
- **Y:** `Сотрудник` · **X:** `Доля занятости` · **Цвет:** `Грейд`, палитра «Грейды»
- **Сортировка:** по сумме X убыв.
- **Зачем.** Мгновенно видно ядро команды (полные ставки) и тех, кто задействован краем. Часто выясняется, что «команда из 12 человек» — это трое полноценных и девять по 20%.

### C1.2 — Стоимость продуктов внутри направления

- **Тип:** Линейчатая
- **Y:** `Продукт` · **X:** `ФОТ, мес` · **Подписи:** ФОТ и FTE
- **Цвет:** один; продукты с `Bus factor` = «Критично: 1 человек» подсветить `#d03b3b` **и добавить иконку** — риск нельзя обозначать одним цветом
- **Зачем.** Внутри направления бюджет распределён неравномерно, и обычно это распределение никто не проверял.

### C1.3 — Матрица «Продукт × Проектная роль»

- **Тип:** Сводная таблица с заливкой
- **Строки:** `Продукт` · **Столбцы:** `Проектная роль` · **Значение:** `FTE`
- **Зачем.** Дыры в команде читаются как пустые клетки: «у продукта есть администратор, но нет ни руководителя продукта, ни специалиста».

### C1.4 — Sankey «Проект → Грейд → Сотрудник»

- **Тип:** Диаграмма Санкей
- **Узлы по порядку:** `Проект` → `Грейд` → `Сотрудник` · **Толщина:** `Доля занятости`
- **Зачем.** Самый убедительный чарт для показа людям: состав команды и переходы людей между продуктами в одной картинке. Если снять фильтр по проекту — видно всю картину пересечений.
- **Нюанс.** Средний уровень обязательно `Грейд` (7 значений), а не `Проектная роль` или `Продукт` — иначе узлов станет столько, что читать будет нечего.

### C1.5 — Реестр команды

Таблица: `Сотрудник` · `Организация` · `Штатная должность` · `Грейд` · `Проектная роль` · `Доля занятости` · `Назначений у сотрудника` · `ЗП` · `Compa-ratio` · `Бейдж ЗП` · `Метка достоверности` · `Руководитель`.

### C2.1 — Разброс зарплат по проектным ролям *(замена box plot)*

DataLens не строит «ящики с усами», поэтому собираем комбинированный чарт из четырёх серий.

- **Тип:** Комбинированная
- **X:** `Проектная роль` (сортировка по `Уровень роли №`)
- **Серия 1, точки:** `ЗП`, детализация до `Сотрудник`. Цвет точки — `Цвет флага`, палитра «Светофор ЗП»
- **Серия 2, линия:** `MEDIAN([ЗП])`, толщина 2 px, нейтральный тёмный — это и есть база сравнения
- **Серии 3–4, тонкие линии:** `QUANTILE([ЗП], 0.25)` и `QUANTILE([ЗП], 0.75)`, приглушённый серый
- **Фильтр:** `В анализе справедливости` = 1
- **Зачем.** Главный диагностический чарт: сколько платят за конкретную работу и кто из этого выбивается. На ваших данных роль «Администратор проекта» растянута от 31 тыс до 251 тыс — восьмикратно при медиане 120 тыс. Одна и та же работа, восьмикратная разница в оплате: с этого чарта начинается любой разбор.
- **Нюанс.** Точки минимум 8 px, с кольцом 2 px цветом фона на пересечениях. Область наведения должна быть больше самой точки.
- **Вариант того же чарта** с X = `Грейд` — справочный. Он показывает, как оплата соотносится со штатным расписанием, но выводов по нему делать нельзя: должность могли назначить под оклад.

### C2.2 — Compa-ratio по сотрудникам

- **Тип:** Линейчатая
- **Y:** `Сотрудник` · **X:** `Отклонение руб` · **Цвет:** `Цвет флага` · **Референсная линия:** 0
- **Сортировка:** X по возрастанию — недоплаченные сверху, с них и начинают
- **Фильтр по умолчанию:** `Требует внимания` = 1
- **Зачем.** Рабочий список на пересмотр, отсортированный по приоритету.
- **Нюанс.** Ось именно в рублях, а не в процентах. Проценты убеждают, а решение принимают по деньгам: «−22%» и «−130 тыс ₽/мес» ощущаются совершенно по-разному. Compa-ratio показывайте в подсказке.

### C2.3 — Типы отклонений

- **Тип:** Линейчатая с накоплением, одна полоса
- **Разбивка:** `Тип отклонения` · **Значение:** `Сотрудников (в срезе)`
- **Цвет:** тип 1 серый `#a8a7a0`, типы 2–3 синие `#184f95`, типы 4–5 красные `#b3261e`
- **Фильтр:** `В анализе справедливости` = 1
- **Зачем.** Раскладывает отклонения по причинам, а не по величине. Пять категорий отвечают на вопрос «почему», а не только «на сколько»:

| Тип | Что означает | Что делать |
|---|---|---|
| 1. Норма | Оплата соответствует работе | — |
| 2. Оплата по должности, а не по роли | Оклад обоснован штатной позицией, объём работы меньше | Разобрать: должность формальна или обязанности шире, чем записано |
| 3. Выше и роли, и должности | Оклад не объясняется ничем формальным | Индивидуальная договорённость — уточнить, чем обоснована |
| 4. Роль выше должности | Человек делает работу выше своей позиции, платят по позиции | Привести должность в соответствие с работой — оклад подтянется следом |
| 5. Недоплата за роль | Недоплачивают и по работе, и по позиции | Прямой кандидат на пересмотр |

- **Обязательно рядом** — тот же разрез в деньгах: `SUM([Отклонение руб])` по типам. Категории 2 и 3 дают +20.9 млн ₽/год, категории 4 и 5 — −32.4 млн ₽/год.

### C2.3б — Матрица «Проектная роль × Грейд»

- **Тип:** Сводная таблица с заливкой
- **Строки:** `Проектная роль` (сортировка по `Уровень роли №`) · **Столбцы:** `Грейд` · **Значение:** `Сотрудников (в срезе)`
- **Второй экземпляр** со значением `AVG([Разрыв должность − роль, руб])`, **диверегирующая** заливка от `#b3261e` через серый к `#184f95`
- **Зачем.** Показывает расхождение записанного и фактического напрямую. На ваших данных под ролью «Администратор проекта» встречаются грейды от G0 до G5: один и тот же объём работы оформлен и стажёром, и руководителем проектов. Клетки выше диагонали — должность выше роли, ниже диагонали — роль выше должности.
- **Нюанс.** Диагональ здесь условная: шкалы R0–R4 и G0–G6 не совпадают по числу ступеней. Поэтому величину расхождения берите из поля `Разрыв должность − роль, руб` — оно выражено в деньгах и сравнимо напрямую.

### C2.4 — Квадрант «зарплата × загрузка»

- **Тип:** Точечная
- **X:** `Назначений у сотрудника` · **Y:** `Compa-ratio` · **Размер:** `ЗП` · **Цвет:** `Грейд`
- **Референсные линии:** X = 1, Y = 1
- **Зачем.** Правый нижний квадрант — люди на нескольких продуктах с зарплатой ниже своей группы. Это главный риск ухода, и никакой другой чарт не покажет его так наглядно.
- **Нюанс.** Подписывать точки только в двух «острых» квадрантах, иначе получится каша.

### C2.5 — Зарплаты по организациям *(контрольный чарт)*

- **Тип:** Комбинированная. **X:** `Грейд` · **Серия-точки:** `MEDIAN([ЗП])` с разбивкой по `Организация`
- **Зачем.** Это проверка, а не аналитика. Разбор показал, что медианы внутри грейда по организациям совпадают — действует единая тарифная сетка. Чарт нужен, чтобы это было видно, и чтобы заметить, если однажды перестанет совпадать: расхождение будет означать, что одна из организаций начала платить по другим правилам.

### C2.6 — Реестр сотрудников *(главная таблица дашборда)*

Колонки в этом порядке:

`Сотрудник` · `Организация` · **`Проектная роль`** · `ЗП` · `База сравнения` · **`Уровень сравнения`** · `Compa-ratio` · `Отклонение руб` · `Z-score` · **`Бейдж ЗП`** · `Штатная должность` · `Грейд` · `Compa-ratio к должности` · **`Бейдж причины`** · **`Метка достоверности`** · `Доплата до порога` · `Проект` · `Руководитель`

Порядок колонок не случаен: сначала роль и всё, что считается от неё, потом должность и диагностика. Читается как «за эту работу платят столько → а по штатке положено столько → отсюда причина».

- Сортировка по умолчанию: `Отклонение руб` по возрастанию
- Условное форматирование на `Compa-ratio`: диверегирующая шкала

> **Колонка «Уровень сравнения» обязательна.** Она честно говорит, на чём основан вывод: «Проектная роль» — вывод крепкий (153 человека), «Уровень роли (мало данных)» — выборка мала (3 человека: роли «Аналитик» и «Руководитель функции»). Без неё дашборд создаёт ложную уверенность, и первый же разбор конкретного кейса подорвёт доверие ко всему остальному.

### C6.3 — Сверка итогов

Небольшая таблица, сравнивающая метрики, посчитанные двумя независимыми способами:

| ФОТ | `SUM([ФОТ аллоцированный])` | `SUM(IF [Первичное назначение]=1 THEN [ЗП] ELSE 0 END)` |
| Проектов | `COUNTD([Проект])` | 12 (константа) |

Расхождение означает, что поехали доли или появились дубли. Самая дешёвая страховка от тихой ошибки в цифрах, которую иначе замечают через полгода.

## Часть 4. Права доступа

Дашборд с зарплатами всей организации — самый чувствительный документ, который у вас будет. **Настраивать до того, как дать кому-либо ссылку.**

| Кто | Что видит |
|---|---|
| Вы, HR, финансы | Всё |
| Ответственный за блок | Свой блок с зарплатами |
| Руководитель | Своих подчинённых |
| Остальные | Обезличенная копия либо ничего |

**RLS** настраивается в датасете, в свойствах поля `Блок`:

```
'user1@company.ru': Радужан А.А.
'user2@company.ru': Зазыкин В.Г., Ульянов А.Ю.
'hr@company.ru': *
```

Проверять обязательно через режим **«Просмотр от имени пользователя»**: на словах RLS всегда настроена правильно, а на практике почти всегда с первого раза протекает.

**Обезличенная копия** — отдельный дашборд на том же датасете, но без полей `ЗП`, `Compa-ratio`, `Отклонение руб`, `База сравнения`, `Доплата до порога`. Остаются состав команд, загрузка, грейды, вакансии, bus factor. Такой дашборд полезен всем и не создаёт рисков.

## Часть 5. Порядок сборки и чек-лист

**Собирайте в таком порядке** — так вы раньше всего поймаете ошибку в расчётах:

1. Датасет, типы, форматы (30 мин).
2. Параметры и поля из части 1 (1 час).
3. **Вкладка 2 целиком** — она даёт результат, ради которого всё затевалось. Сразу после сборки проверьте Compa-ratio вручную на 3–5 знакомых людях. Если для кого-то цифра странная — почти всегда дело в грейде, и лучше выяснить это на пятом чарте, а не на тридцатом.
4. Вкладка 0.
5. Вкладки 1, 3, 4.
6. Вкладка 6.
7. RLS.

Именуйте чарты по схеме `[2] Compa-ratio по сотрудникам` — через месяц в списке из тридцати это будет единственный способ что-то найти. Дублируйте готовые чарты через «Сохранить как» и меняйте одну метрику: быстрее, чем собирать заново.

### Чек-лист приёмки

**Расчёты**
- [ ] `SUM([Первичное назначение])` = `COUNTD([Сотрудник])` = 180
- [ ] `SUM([ФОТ аллоцированный])` = 31.7 млн, сходится со вторым способом
- [ ] Compa-ratio проверен вручную минимум на 5 сотрудниках
- [ ] Вакансии не попадают в численность, ФОТ и среднюю ЗП
- [ ] Роль «Стажёр» исключена из светофора (`В анализе справедливости` = 0)
- [ ] Колонка «Уровень сравнения» есть в реестре
- [ ] База сравнения считается по **проектной роли**, а не по должности — проверьте на человеке из категории «Оплата по должности, а не по роли»: его Compa-ratio должен быть заметно больше 1

**Оформление**
- [ ] Ни один чарт не красит 12 проектов в 12 цветов
- [ ] Ни одного чарта с двумя осями Y
- [ ] Грейд и уровень роли везде красятся порядковой шкалой, а не категориальной
- [ ] Светофор несёт три цвета; пятиуровневая градация — текстом и стрелками
- [ ] Деньги отформатированы в разрядах с ₽
- [ ] У каждого чарта есть подпись, объясняющая, что в нём искать
- [ ] Селекторы одной строкой сверху и влияют на все чарты вкладки (проверено в «Связях»)
- [ ] Проверено в тёмной теме

**Доступы**
- [ ] RLS настроена и проверена «от имени пользователя»
- [ ] Решено, кому доступна обезличенная копия
- [ ] Исходный Excel не содержит листов с расшифровкой идентификаторов

## Часть 6. Как этим пользоваться дальше

Дашборд сам по себе ничего не меняет. Работает регулярный цикл:

**Ежемесячно, 15 минут.** Перегенерировать датасет с новым `--snapshot`, открыть вкладку 6 (данные в порядке?), затем вкладку 3 (кто перегружен). Поправить назначения.

**Ежеквартально, 1–2 часа.** Вкладка 2, но не весь список подряд — по категориям, у каждой своё действие:

- **«Роль выше должности»** (самая большая группа) — привести должность в соответствие с работой. Оклад подтянется следом, и это дешевле, чем разовая доплата.
- **«Оплата по должности, а не по роли»** — разобрать поштучно: должность формальна или обязанности реально шире, чем записано в роли. Если второе — надо править роль в таблице, а не зарплату.
- **«Недоплата за роль»** — прямой кандидат на пересмотр.
- **«Выше и роли, и должности»** — уточнить, чем обоснована индивидуальная договорённость.

**Записывать причину по каждому решению.** Через два-три квартала накопленные причины станут тем, чего сейчас не хватает, — и Compa-ratio из списка на разбор превратится в вердикт.

**Раз в полгода.** Вкладки 4 и 0. Оргструктура меняется медленно.

**Перед бюджетированием.** What-if калькулятор и плитка «стоимость вакансий»: три сценария индексации плюс прогноз прироста ФОТ при закрытии набора. Разговор с финансами идёт по числам, а не по ощущениям.
