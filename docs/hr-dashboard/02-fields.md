# 02. Каталог вычисляемых полей DataLens

Все формулы — на языке формул DataLens (раздел «Поля» в датасете). Копируются как есть, названия полей подставьте свои.

**Соглашения:**
- `[ЗП]` — столбец «Текущая ЗП, gross»
- `[Доля]` — «Доля занятости» (0–1)
- `[Первичное]` — флаг первичного назначения (0/1)
- `[ФИО]`, `[Проект]`, `[Продукт]`, `[Роль]`, `[Грейд]`, `[Руководитель]`, `[Ответственный]` — как в таблице
- ⚙️ — поле-параметр, создаётся в разделе «Параметры» датасета/дашборда
- ⚠️ — формула использует LOD/оконные функции: проверьте результат на своих данных, поведение зависит от того, какие измерения стоят в чарте

> **О синтаксисе.** DataLens периодически расширяет набор функций, и в вашей версии какая-то может называться иначе (например, `QUANTILE` vs `PERCENTILE`). Редактор формул подсказывает доступные имена по мере ввода — если что-то не принимается, ищите ближайший аналог там. Логика формул от этого не меняется.

## Группа 1. Базовые ключи и нормализация

| № | Название поля | Формула | Комментарий |
|---|---|---|---|
| 1.1 | `Продукт_ключ` | `CONCAT([Проект], ' / ', [Продукт])` | Уникальный ключ продукта. Обязательно — названия продуктов повторяются между проектами |
| 1.2 | `ФИО_норм` | `TRIM([ФИО])` | Защита от хвостовых пробелов |
| 1.3 | `Роль_норм` | `TRIM([Роль])` | То же |
| 1.4 | `Доля_норм` | `IF ISNULL([Доля]) OR [Доля] = 0 THEN 1 ELSE [Доля] END` | Страховка: пустая доля не должна обнулять человека |
| 1.5 | `Грейд_норм` | `IF ISNULL([Грейд]) OR [Грейд] = '' THEN 'Не указан' ELSE [Грейд] END` | Пустые грейды не должны выпадать из группировок |
| 1.6 | `Грейд_порядок` | `CASE [Грейд_норм] WHEN 'Intern' THEN 1 WHEN 'Junior' THEN 2 WHEN 'Middle' THEN 3 WHEN 'Senior' THEN 4 WHEN 'Lead' THEN 5 WHEN 'Head' THEN 6 ELSE 9 END` | Чтобы грейды на осях шли по старшинству, а не по алфавиту |
| 1.7 | `Функция` | `IF CONTAINS(LOWER([Роль]), 'разработ') OR CONTAINS(LOWER([Роль]), 'developer') OR CONTAINS(LOWER([Роль]), 'программ') THEN 'Разработка' ELSEIF CONTAINS(LOWER([Роль]), 'тест') OR CONTAINS(LOWER([Роль]), 'qa') THEN 'Тестирование' ELSEIF CONTAINS(LOWER([Роль]), 'аналит') THEN 'Аналитика' ELSEIF CONTAINS(LOWER([Роль]), 'дизайн') THEN 'Дизайн' ELSEIF CONTAINS(LOWER([Роль]), 'руковод') OR CONTAINS(LOWER([Роль]), 'менеджер') OR CONTAINS(LOWER([Роль]), 'lead') OR CONTAINS(LOWER([Роль]), 'head') THEN 'Менеджмент' ELSE 'Прочее' END` | Если столбца `Функция` нет в источнике — вывести из роли. Проверьте, что в «Прочее» не улетело больше 10% строк |
| 1.8 | `Менеджерская роль` | `IF CONTAINS(LOWER([Роль]), 'руковод') OR CONTAINS(LOWER([Роль]), 'lead') OR CONTAINS(LOWER([Роль]), 'head') OR CONTAINS(LOWER([Роль]), 'директор') OR CONTAINS(LOWER([Роль]), 'менеджер прое') THEN 1 ELSE 0 END` | Для расчёта доли менеджерского слоя |

## Группа 2. Численность и объём

| № | Название | Формула | Комментарий |
|---|---|---|---|
| 2.1 | `Сотрудников` | `COUNTD([ФИО_норм])` | Уникальные люди в текущем срезе |
| 2.2 | `Сотрудников (надёжно)` | `SUM([Первичное])` | ⚠️ Работает только без фильтра по проекту — считает людей глобально. Для проверки итогов |
| 2.3 | `Назначений` | `COUNT([№])` | Число строк = число «человеко-ролей» |
| 2.4 | `Проектов` | `COUNTD([Проект])` | |
| 2.5 | `Продуктов` | `COUNTD([Продукт_ключ])` | |
| 2.6 | `Ролей` | `COUNTD([Роль_норм])` | |
| 2.7 | `FTE` | `SUM([Доля_норм])` | Полных ставок в срезе. Главная метрика объёма |
| 2.8 | `Назначений на человека` | `COUNT([№]) / COUNTD([ФИО_норм])` | Индекс размазанности. Норма ≤ 1.5 |
| 2.9 | `Проектов у сотрудника` | `COUNTD([Проект] FIXED [ФИО_норм])` | ⚠️ Число направлений конкретного человека |
| 2.10 | `Занятость сотрудника всего` | `SUM([Доля_норм] FIXED [ФИО_норм])` | ⚠️ Суммарная загрузка человека по всем проектам. >1 = перегруз |
| 2.11 | `Мультипроектный` | `IF [Проектов у сотрудника] > 1 THEN 'Да' ELSE 'Нет' END` | ⚠️ |
| 2.12 | `Доля мультипроектных` | `COUNTD(IF [Проектов у сотрудника] > 1 THEN [ФИО_норм] END) / COUNTD([ФИО_норм])` | ⚠️ Формат: процент |

## Группа 3. Деньги

### 3.1. Параметры (создаются один раз)

| № | Параметр | Тип | Значение по умолчанию | Зачем |
|---|---|---|---|---|
| ⚙️ 3.1.1 | `p_Взносы` | число | `0.302` | Страховые взносы. Для аккредитованных IT — `0.076` |
| ⚙️ 3.1.2 | `p_Накладные` | число | `15000` | Рабочее место, техника, софт, ДМС на человека в месяц |
| ⚙️ 3.1.3 | `p_Индексация` | число | `10` | % повышения для what-if сценария |
| ⚙️ 3.1.4 | `p_Порог_недоплаты` | число | `0.90` | Граница Compa-ratio для флага «ниже группы» |
| ⚙️ 3.1.5 | `p_Порог_переплаты` | число | `1.30` | Граница для флага «переплата» |
| ⚙️ 3.1.6 | `p_Мин_группа` | число | `4` | Минимальный размер группы «Роль × Грейд» для сравнения |

Параметры выносятся на дашборд селекторами — пользователь крутит пороги и сразу видит, как меняются списки. Это резко повышает доверие: человек сам убеждается, что выводы устойчивы.

### 3.2. Метрики ФОТ

| № | Название | Формула | Комментарий |
|---|---|---|---|
| 3.2.1 | `ФОТ аллоц., мес` | `SUM([ЗП] * [Доля_норм])` | **Основная метрика денег.** Корректна в любом разрезе, суммы сходятся |
| 3.2.2 | `ФОТ уник., мес` | `SUM(IF [Первичное] = 1 THEN [ЗП] ELSE 0 END)` | Настоящий ФОТ без аллокации. Для сверки итога |
| 3.2.3 | `ФОТ, год` | `[ФОТ аллоц., мес] * 12` | |
| 3.2.4 | `Полная стоимость, мес` | `[ФОТ аллоц., мес] * (1 + [p_Взносы]) + [p_Накладные] * [FTE]` | ⚙️ Реальные затраты. Обычно на 35–40% выше gross |
| 3.2.5 | `Полная стоимость, год` | `[Полная стоимость, мес] * 12` | Цифра для разговора с финансами |
| 3.2.6 | `Средняя ЗП` | `AVG([ЗП] FIXED [ФИО_норм])` | ⚠️ FIXED убирает перекос от мультипроектных. Если LOD ведёт себя не так, используйте 3.2.7 |
| 3.2.7 | `Средняя ЗП (надёжно)` | `SUM(IF [Первичное]=1 THEN [ЗП] ELSE 0 END) / SUM([Первичное])` | Без LOD, но корректно только без фильтра по проекту |
| 3.2.8 | `Медианная ЗП` | `MEDIAN([ЗП])` | Устойчивее среднего к выбросам. Показывайте обе |
| 3.2.9 | `Разрыв среднее/медиана` | `[Средняя ЗП] / [Медианная ЗП]` | > 1.15 = сильный перекос вверх, несколько человек тянут среднее |
| 3.2.10 | `Мин ЗП` | `MIN([ЗП])` | |
| 3.2.11 | `Макс ЗП` | `MAX([ЗП])` | |
| 3.2.12 | `Разброс ЗП (раз)` | `MAX([ЗП]) / MIN([ЗП])` | Внутрикомандное неравенство. > 6 в одной команде — повод разобраться |
| 3.2.13 | `Коэф. вариации ЗП` | `STDEV([ЗП]) / AVG([ЗП])` | Формат: процент. > 45% внутри одной роли — либо грейды не проставлены, либо реальный разнобой |
| 3.2.14 | `Стоимость FTE` | `[ФОТ аллоц., мес] / [FTE]` | Средняя цена полной ставки. Хорошая метрика для сравнения проектов между собой |
| 3.2.15 | `ФОТ на человека` | `[ФОТ аллоц., мес] / COUNTD([ФИО_норм])` | |
| 3.2.16 | `Доля ФОТ от общего` | `[ФОТ аллоц., мес] / SUM([ЗП] * [Доля_норм] TOTAL)` | ⚠️ Оконная функция. Формат: процент |

## Группа 4. Справедливость оплаты — ядро дашборда

### 4.1. Базы сравнения

| № | Название | Формула | Комментарий |
|---|---|---|---|
| 4.1.1 | `Медиана по роли` | `MEDIAN([ЗП] FIXED [Роль_норм])` | ⚠️ |
| 4.1.2 | `Медиана по роли+грейду` | `MEDIAN([ЗП] FIXED [Роль_норм], [Грейд_норм])` | ⚠️ Точнее, но требует достаточного размера группы |
| 4.1.3 | `Людей в группе Роль+Грейд` | `COUNTD([ФИО_норм] FIXED [Роль_норм], [Грейд_норм])` | ⚠️ |
| 4.1.4 | `Людей в роли` | `COUNTD([ФИО_норм] FIXED [Роль_норм])` | ⚠️ |
| 4.1.5 | **`База сравнения`** | `IF [Людей в группе Роль+Грейд] >= [p_Мин_группа] THEN [Медиана по роли+грейду] ELSEIF [Людей в роли] >= [p_Мин_группа] THEN [Медиана по роли] ELSE [Медиана по функции] END` | ⚙️⚠️ **Ключевое поле.** Каскадный откат: если группа слишком мала для статистики, поднимаемся на уровень выше |
| 4.1.6 | `Медиана по функции` | `MEDIAN([ЗП] FIXED [Функция])` | ⚠️ Последний уровень отката |
| 4.1.7 | `Уровень сравнения` | `IF [Людей в группе Роль+Грейд] >= [p_Мин_группа] THEN 'Роль + грейд' ELSEIF [Людей в роли] >= [p_Мин_группа] THEN 'Роль' ELSE 'Функция (мало данных)' END` | ⚙️⚠️ Показывать в таблице — честность про качество вывода. Пользователь должен видеть, что для роли из 2 человек сравнение слабое |

### 4.2. Метрики отклонения

| № | Название | Формула | Комментарий |
|---|---|---|---|
| 4.2.1 | **`Compa-ratio`** | `AVG([ЗП]) / [База сравнения]` | ⚠️ Главная метрика. 1.0 = ровно по группе |
| 4.2.2 | `Отклонение, %` | `([Compa-ratio] - 1) * 100` | Читается проще, чем ratio |
| 4.2.3 | `Отклонение, ₽` | `AVG([ЗП]) - [База сравнения]` | Отклонение в деньгах. Именно эта цифра нужна для решения |
| 4.2.4 | `Z-score по роли` | `(AVG([ЗП]) - AVG([ЗП] FIXED [Роль_норм])) / STDEV([ЗП] FIXED [Роль_норм])` | ⚠️ Насколько выброс статистически необычен. \|Z\| > 2 — сильный выброс |
| 4.2.5 | `Перцентиль в роли` | `RANK_PERCENTILE(AVG([ЗП]) WITHIN [Роль_норм])` | ⚠️ Позиция человека внутри своей роли, 0–1 |
| 4.2.6 | `Q1 по роли` | `QUANTILE([ЗП], 0.25 FIXED [Роль_норм])` | ⚠️ |
| 4.2.7 | `Q3 по роли` | `QUANTILE([ЗП], 0.75 FIXED [Роль_норм])` | ⚠️ |
| 4.2.8 | `Верхняя граница (IQR)` | `[Q3 по роли] + 1.5 * ([Q3 по роли] - [Q1 по роли])` | ⚠️ Классическое правило выброса |
| 4.2.9 | `Нижняя граница (IQR)` | `[Q1 по роли] - 1.5 * ([Q3 по роли] - [Q1 по роли])` | ⚠️ |
| 4.2.10 | `Выброс по IQR` | `IF AVG([ЗП]) > [Верхняя граница (IQR)] THEN 'Выброс вверх' ELSEIF AVG([ЗП]) < [Нижняя граница (IQR)] THEN 'Выброс вниз' ELSE 'В норме' END` | ⚠️ Независимая от Compa-ratio проверка. Смотрите пересечение двух методов — там самые надёжные кейсы |

### 4.3. Светофор

| № | Название | Формула |
|---|---|---|
| 4.3.1 | **`Флаг ЗП`** | `IF [Compa-ratio] < 0.80 THEN '1. Недоплата' ELSEIF [Compa-ratio] < [p_Порог_недоплаты] THEN '2. Ниже группы' ELSEIF [Compa-ratio] <= 1.15 THEN '3. Норма' ELSEIF [Compa-ratio] <= [p_Порог_переплаты] THEN '4. Выше группы' ELSE '5. Переплата' END` |

Цифровой префикс — чтобы легенда и оси сортировались от недоплаты к переплате, а не по алфавиту. В подписях чарта префикс убирается.

| № | Название | Формула | Комментарий |
|---|---|---|---|
| 4.3.2 | `Флаг ЗП (цвет)` | `IF [Compa-ratio] < [p_Порог_недоплаты] THEN 'Недоплата' ELSEIF [Compa-ratio] > 1.15 THEN 'Переплата' ELSE 'Норма' END` | ⚙️ **Три класса — именно столько несёт цвет.** Пятиуровневая градация остаётся в тексте и в числе, но не в цвете (обоснование — `03-charts.md`, A.2) |
| 4.3.3 | `Флаг ЗП (бейдж)` | `CASE [Флаг ЗП] WHEN '1. Недоплата' THEN COLOR(BOLD('▼▼ Недоплата'), '#b3261e') WHEN '2. Ниже группы' THEN COLOR('▼ Ниже группы', '#b3261e') WHEN '3. Норма' THEN COLOR('● Норма', '#52514e') WHEN '4. Выше группы' THEN COLOR('▲ Выше группы', '#184f95') ELSE COLOR(BOLD('▲▲ Переплата'), '#184f95') END` | Markup-поле для таблиц. Все пять уровней различимы: направление — цветом, степень — стрелками и жирностью. Так бейдж читается и на чёрно-белой печати, и при дальтонизме |
| 4.3.4 | `Требует внимания` | `IF [Compa-ratio] < [p_Порог_недоплаты] OR [Compa-ratio] > [p_Порог_переплаты] OR ABS([Z-score по роли]) > 2 THEN 1 ELSE 0 END` | ⚙️⚠️ Для KPI «людей на ревью» |
| 4.3.5 | `Людей на ревью` | `COUNTD(IF [Требует внимания] = 1 THEN [ФИО_норм] END)` | ⚠️ |

### 4.4. Сравнение с рынком (нужен справочник `dim_Рынок`)

| № | Название | Формула | Комментарий |
|---|---|---|---|
| 4.4.1 | `Compa-ratio к рынку` | `AVG([ЗП]) / AVG([Рынок P50])` | 1.0 = по медиане рынка |
| 4.4.2 | `Позиция в рыночной вилке` | `IF AVG([ЗП]) < AVG([Рынок P25]) THEN 'Ниже вилки' ELSEIF AVG([ЗП]) <= AVG([Рынок P50]) THEN 'Нижняя половина' ELSEIF AVG([ЗП]) <= AVG([Рынок P75]) THEN 'Верхняя половина' ELSE 'Выше вилки' END` | |
| 4.4.3 | `Риск ухода` | `IF AVG([ЗП]) < AVG([Рынок P25]) THEN 'Высокий' ELSEIF AVG([ЗП]) < AVG([Рынок P50]) THEN 'Средний' ELSE 'Низкий' END` | Внутренняя справедливость и рыночный риск — разные вещи. Человек может быть выше всех внутри и всё равно ниже рынка |
| 4.4.4 | `Разрыв с рынком, ₽` | `AVG([Рынок P50]) - AVG([ЗП])` | Стоимость закрытия разрыва по человеку |

### 4.5. What-if: сколько стоит выровнять

| № | Название | Формула | Комментарий |
|---|---|---|---|
| 4.5.1 | `ЗП после индексации` | `AVG([ЗП]) * (1 + [p_Индексация] / 100)` | ⚙️ |
| 4.5.2 | `Стоимость выравнивания до порога, мес` | `SUM(IF [Compa-ratio] < [p_Порог_недоплаты] AND [Первичное] = 1 THEN [База сравнения] * [p_Порог_недоплаты] - [ЗП] ELSE 0 END)` | ⚙️⚠️ **Самая полезная цифра дашборда.** Сколько денег в месяц нужно, чтобы не осталось недоплаченных |
| 4.5.3 | `Стоимость выравнивания, год` | `[Стоимость выравнивания до порога, мес] * 12` | |
| 4.5.4 | `Стоимость с взносами, год` | `[Стоимость выравнивания, год] * (1 + [p_Взносы])` | ⚙️ Настоящая цена решения |
| 4.5.5 | `Прирост ФОТ от индексации, %` | `[Стоимость выравнивания до порога, мес] / [ФОТ уник., мес]` | Формат: процент. Ставит цену в контекст |
| 4.5.6 | `Экономия от нормализации переплат` | `SUM(IF [Compa-ratio] > [p_Порог_переплаты] AND [Первичное] = 1 THEN [ЗП] - [База сравнения] * [p_Порог_переплаты] ELSE 0 END)` | ⚙️⚠️ Обратная сторона. Не для сокращений — для понимания, где не надо повышать |

## Группа 5. Загрузка и пересечения

| № | Название | Формула | Комментарий |
|---|---|---|---|
| 5.1 | `Статус загрузки` | `IF [Занятость сотрудника всего] > 1.1 THEN 'Перегруз' ELSEIF [Занятость сотрудника всего] >= 0.9 THEN 'Норма' ELSEIF [Занятость сотрудника всего] >= 0.5 THEN 'Недогруз' ELSE 'Слабая загрузка' END` | ⚠️ |
| 5.2 | `Коэф. переключения` | `CASE [Проектов у сотрудника] WHEN 1 THEN 1.0 WHEN 2 THEN 0.9 WHEN 3 THEN 0.8 ELSE 0.7 END` | ⚠️ Штраф за context switching. Коэффициенты подберите под себя |
| 5.3 | `Эффективный FTE` | `SUM([Доля_норм] * [Коэф. переключения])` | ⚠️ Сколько реальной работы получается из номинальных ставок |
| 5.4 | `Потери на переключении, FTE` | `[FTE] - [Эффективный FTE]` | |
| 5.5 | `Потери на переключении, ₽/мес` | `SUM([ЗП] * [Доля_норм] * (1 - [Коэф. переключения]))` | ⚠️ **Цена организационной размазанности в рублях.** Обычно шокирует — и именно поэтому работает |
| 5.6 | `Доля в проекте (от человека)` | `SUM([Доля_норм]) / [Занятость сотрудника всего]` | ⚠️ Какую часть своего времени человек отдаёт этому проекту |
| 5.7 | `Шаренных людей в проекте` | `COUNTD(IF [Проектов у сотрудника] > 1 THEN [ФИО_норм] END)` | ⚠️ |
| 5.8 | `Доля шаренных в проекте` | `[Шаренных людей в проекте] / COUNTD([ФИО_норм])` | ⚠️ Формат: процент. > 50% — проект живёт на заёмных руках, риск срыва сроков |

## Приложение. Если LOD-выражения работают не так, как ожидалось

`FIXED` в DataLens вычисляет агрегат по указанным измерениям, а затем «поднимает» результат к уровню детализации чарта. В большинстве случаев это работает интуитивно, но при сложных комбинациях фильтров результат может удивить.

Три надёжных обходных пути, в порядке предпочтения:

1. **Посчитать в источнике.** Медиана по роли, число проектов у сотрудника, суммарная занятость — всё это спокойно считается формулами в Google Sheets (`MEDIAN(IF(...))`, `COUNTIF`, `SUMIF`) и приезжает в DataLens готовым столбцом. Формулы прозрачны, результат проверяется глазами. **Для зарплатного дашборда это лучший вариант** — цена ошибки здесь высокая.
2. **Отдельный датасет-справочник.** Для метрик уровня «сотрудник» (уникальный ФОТ, средняя ЗП, распределение) постройте чарты на `dim_Сотрудники`, где одна строка = один человек. Тогда обычный `SUM`/`AVG` корректен по определению, без всякого LOD.
3. **`BEFORE FILTER BY`.** Если база сравнения «съезжает» при выборе проекта в селекторе — это как раз нужное поведение по умолчанию (медиана считается по отфильтрованной выборке). Если же вы хотите, чтобы медиана всегда считалась по всей компании независимо от фильтров, добавьте `BEFORE FILTER BY`:
   ```
   MEDIAN([ЗП] FIXED [Роль_норм] BEFORE FILTER BY [Проект])
   ```
   **Это важное решение, а не деталь:** сравнивать зарплату разработчика надо с медианой по всем разработчикам компании, а не с медианой внутри выбранного проекта, где их может быть двое. Рекомендую все базы сравнения (поля 4.1.1–4.1.6) делать с `BEFORE FILTER BY` по проекту, продукту и руководителю.
