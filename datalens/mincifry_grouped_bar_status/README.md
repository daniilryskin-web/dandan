# Advanced-чарт DataLens: ОЦС и ДК по статусам

Восьмой чарт набора: по вертикали статусы, затем причины выбытия и
вычисляемые «Оставшиеся»; внутри каждой группы — полоса ОЦС и полоса ДК. Рендер тот же, что в `../mincifry_grouped_bar_chart`; отличия —
константы, сортировка по номеру статуса и адаптивная колонка подписей.

## Раскладка по вкладкам

| Файл | Вкладка |
|---|---|
| `Meta.json` | Meta |
| `Params.js` | Params |
| `Sources.js` | Sources |
| `Prepare.js` | Prepare |
| `Controls.js` | Controls |

## Подключение датасета

Во вкладку **Meta** вписываются **два** ключа:

```json
{"links": {
    "statusDataset": "<id датасета со статусами>",
    "extraDataset": "<id датасета со скалярными мерами>"
}}
```

Если все поля лежат в одном датасете — впишите один и тот же id обоим ключам.
Ключи разные на случай, если меры формулы лежат в другом датасете.

Id берётся из адреса **датасета**, а не воркбука: в
`.../workbooks/<id воркбука>/datasets/<id датасета>` нужен последний.

## Два источника

`Sources.js` делает два запроса, потому что у наборов разная форма:

* `status` — строки по статусам: измерение `Статус` и меры `ОЦС2 (индикатор)`,
  `ДК2 (индикатор)`;
* `extra` — скалярные меры без измерения: «Не требуется», «Перенос на 2027»,
  «Исключены работы в 2026» и слагаемые формулы.

Скалярные меры не разложены по статусам. В одном запросе с измерением `Статус`
они либо размножились бы по строкам, либо распались непредсказуемо; отдельный
запрос без измерения возвращает ровно одну строку с итогами.

Имена полей должны совпадать с датасетом дословно.

У серий есть `aliases`: если поле называется просто `ОЦС` или `ДК` (как было
в визарде), чарт возьмёт его. В легенде показывается `label` — «ОЦС» и «ДК»,
без суффикса «(индикатор)».

## Дополнительные группы

Пять новых полей дают три пары ОЦС / ДК, и каждая пара становится отдельной
группой — ровно так же, как статус:

| Группа | ОЦС | ДК |
|---|---|---|
| Не требуется | `Не требуется ОЦС` | `Не требуется ДК` |
| Перенос на 2027 | `Перенос на 2027 ОЦС` | `Перенос на 2027 ДК` |
| Исключены работы в 2026 | `Исключены работы в 2026 ОЦС` | `Исключены работы в 2026 ДК` |

Задаются в `EXTRA_GROUPS`; у каждого поля есть запасные имена с суффиксом
«(индикатор)».

Группа попадает в чарт, только если хотя бы одно её поле реально пришло:
группа из нулей выглядела бы как настоящие данные. Недостающие поля
перечисляются подписью под заголовком — по той же причине.

## Оставшиеся

Считаются по вашей формуле, отдельно для каждого трека:

```
Оставшиеся ОЦС = ВСЕГО услуг − ЛиР (ниже не приводятся)
               − Не требуется ОЦС − Перенос на 2027 ОЦС
               − Исключены работы в 2026 ОЦС

Оставшиеся ДК  = ВСЕГО услуг − ЛиР (ниже не приводятся)
               − Не требуется ДК − Перенос на 2027 ДК
               − Исключены работы в 2026 ДК
```

В коде это `REMAINING`: `base` — уменьшаемое, `common` — что вычитается у обоих
треков, `perSeries` — что вычитается у своего.

В подсказке этой группы стоят оба числа: результат формулы и сумма по
статусам. Они должны совпадать — «Оставшиеся» и есть пул, разложенный по
статусам. Разойдутся — это видно сразу, без ручного пересчёта.

**Цена группы:** её полоса по построению самая длинная и сжимает статусы на
общей шкале. Если важнее читаемость статусов — `REMAINING.enabled = false`,
и формула исчезает из чарта, оставаясь в коде.

## Фильтр по статусу

«Статус не принадлежит множеству» из вашего визарда:

```js
const EXCLUDE_CATEGORIES = ['Уровень достижения, %'];
```

Отсев идёт до сборки модели, поэтому скрытый статус не влияет ни на порядок
групп, ни на максимум шкалы. Сравнение мягкое: неразрывный пробел, двойные
пробелы и регистр совпадению не мешают.

Фильтр сделан здесь, а не в источнике: имена операций BI API публично не
документированы и расходятся между версиями, ошибка в фильтре роняет весь
чарт. Вариант `operation: 'NIN'` лежит комментарием в `Sources.js`.

## Порядок статусов

Сортировка по номеру в начале подписи: 0., 1., 2., 3., 4., 5.
(`SORT_BY_NUMBER`). Порядок источника произвольный, а сортировка строк
поставила бы «10.» перед «2.».

## Цифры и подписи

Значение стоит внутри полосы у её конца; если полоса короче подписи — сразу
за концом. Нулевое значение полосой не нарисовать, поэтому «0» ставится
приглушённым у оси: иначе статус «4. Вынесено на ПК» выглядел бы пропущенным.

Колонка подписей считается по самой длинной из них и ограничена
`maxLabelWidth` (220 px) и третью ширины холста; что не влезло — усекается
многоточием, полный текст в подсказке.

## Проверка

```
node dev/check.js                # изоляция рендера + четыре размера холста
node dev/preview.js 1000 620     # обновляет preview.html
```

## Что проверено

* Рендер в Chromium на 1000×760: значения по статусам 1/1, 1/1, 1/4, 87/99,
  0/0, 77/46 — совпадают с вашим визардом; дальше идут три новые группы и
  «Оставшиеся» 167 / 151.
* Формула сверена с суммой по статусам на данных предпросмотра: 167 = 167 и
  151 = 151.
* Проверено поведение при отсутствии полей: группа «Перенос на 2027» исчезает
  целиком, если не пришло ни одно её поле, а недостающие имена выводятся
  подписью под заголовком.
* Строки в `dev/fixture.js` намеренно перемешаны и содержат «Уровень
  достижения, %»: чарт восстанавливает порядок 0.–5. и отсеивает лишний
  статус.
* `dev/check.js` проходит на четырёх размерах холста.

Не проверено вживую (нет доступа к инстансу DataLens): поведение
`Editor.generateHtml` на SVG-разметке и точные имена полей.
