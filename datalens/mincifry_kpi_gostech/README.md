# Advanced-чарт DataLens: индикатор «Доля услуг Гостех»

Шестой чарт набора: одно число крупно — «Доля услуг Гостех», с фильтром по
типу, как в визарде. Рендер тот же, что в `../mincifry_kpi_indicator`,
отличаются только константы: поле фильтра, поле значения и заголовок.

## Раскладка по вкладкам

| Файл | Вкладка |
|---|---|
| `Meta.json` | Meta |
| `Params.js` | Params |
| `Sources.js` | Sources |
| `Prepare.js` | Prepare |
| `Controls.js` | Controls |

## Подключение датасета

Во вкладку **Meta** обязательно вписывается id датасета:

```json
{"links": {"gostechDataset": "<id из адреса .../datasets/ID>"}}
```

Имена полей — `FILTER_FIELD` и `VALUE_FIELD` в `Prepare.js` и `fields` в
`Sources.js`.

## Фильтр по типу

Тот же, что у вас в визарде («Тип: Услуг Гостех»), задан списком:

```js
const FILTER_VALUES = ['Услуг Гостех'];
```

Отбор идёт во вкладке `Prepare`, а не в источнике. Причина та же, что и в
чарте по направлениям: строк здесь единицы, а имена операций фильтра BI API
публично не документированы и расходятся между версиями — ошибка в фильтре
роняет весь чарт, как было с `direction: 'ASC'`. Вариант для источника
(`operation: 'IN'`) лежит комментарием в `Sources.js`.

Строка должна совпадать со значением в датасете точно. В фильтре визарда чип
показан как «Тип: Услуг Гостех» — если в данных записано иначе (например,
«Услуги Гостех»), индикатор покажет прочерк и назовёт, чего не нашёл, а
строку нужно будет поправить в `FILTER_VALUES`.

Параметр `filter` перекрывает список: раскомментируйте селектор в
`Controls.js` — и тип можно будет переключать руками, `Prepare` уже это
поддерживает.

## Значение

Поле `Доля услуг Гостех` в вашем датасете вычисляемое и может отдавать
как число, так и готовую строку «45 %». Обрабатываются оба случая:

* пришло число (или строка, которая разбирается в число) — оно форматируется
  как «1 234,5» и к нему дописывается `VALUE_SUFFIX` (` %`);
* пришла строка, не разбирающаяся в число, — показывается как есть.

Берётся первая строка с непустым значением: строки с пустым показателем для
индикатора бесполезны.

Кегль числа подбирается под холст — и по высоте, и по длине строки, иначе
длинное значение вроде «1 234,5 %» вылезало бы за край.

## Полоса выполнения

Под числом рисуется полоса заполнения (`SHOW_PROGRESS`, шкала `PROGRESS_MAX`
= 100). Этого не было в вашем визарде — добавил, потому что доля от 100 %
читается быстрее числа; `SHOW_PROGRESS = false` убирает полосу, и остаётся
ровно то, что было.

## Проверка

```
node dev/check.js               # изоляция рендера + четыре размера холста
node dev/preview.js 420 200     # обновляет preview.html
```

## Что проверено

* Два состояния в Chromium на 420×200: значение есть («43 %») и фильтр ничего
  не нашёл — прочерк с пояснением «Нет строки со значением „Услуг Гостех“ в
  поле „Тип“». Остальное поведение (подбор кегля, разделитель разрядов,
  маленький холст) проверено на парном индикаторе — рендер тот же.
* `dev/check.js` проходит на четырёх размерах холста.

Не проверено вживую (нет доступа к инстансу DataLens): поведение
`Editor.generateHtml` на SVG-разметке и точное значение поля «Тип».
