# Advanced-чарт DataLens: индикатор

Пятый чарт набора: одно число крупно — «Уровень достижения ОЦС», с фильтром по
статусу, как в визарде.

## Раскладка по вкладкам

| Файл | Вкладка |
|---|---|
| `Meta.json` | Meta |
| `Params.js` | Params |
| `Sources.js` | Sources |
| `Prepare.js` | Prepare |
| `Controls.js` | Controls |

## Подключение датасета

Во вкладку **Meta** обязательно вписывается id датасета:

```json
{"links": {"kpiDataset": "<id из адреса .../datasets/ID>"}}
```

Имена полей — `STATUS_FIELD` и `VALUE_FIELD` в `Prepare.js` и `fields` в
`Sources.js`.

## Фильтр по статусу

Тот же, что у вас в визарде («Статус» принадлежит множеству), задан списком:

```js
const STATUS_FILTER = ['Уровень достижения, %'];
```

Отбор идёт во вкладке `Prepare`, а не в источнике. Причина та же, что и в
чарте по направлениям: строк здесь единицы, а имена операций фильтра BI API
публично не документированы и расходятся между версиями — ошибка в фильтре
роняет весь чарт, как было с `direction: 'ASC'`. Вариант для источника
(`operation: 'IN'`) лежит комментарием в `Sources.js`.

Если фильтр не совпал ни с одной строкой, индикатор показывает прочерк и
поясняет, какого статуса не нашлось: пустая плитка без объяснения читается как
поломка.

Параметр `status` перекрывает список: раскомментируйте селектор в
`Controls.js` — и статус можно будет переключать руками, `Prepare` уже это
поддерживает.

## Значение

Поле `Уровень достижения ОЦС` в вашем датасете вычисляемое и может отдавать
как число, так и готовую строку «45 %». Обрабатываются оба случая:

* пришло число (или строка, которая разбирается в число) — оно форматируется
  как «1 234,5» и к нему дописывается `VALUE_SUFFIX` (` %`);
* пришла строка, не разбирающаяся в число, — показывается как есть.

Берётся первая строка с непустым значением: у строк статусов показатель пуст,
и для индикатора они бесполезны.

Кегль числа подбирается под холст — и по высоте, и по длине строки, иначе
длинное значение вроде «1 234,5 %» вылезало бы за край.

## Полоса выполнения

Под числом рисуется полоса заполнения (`SHOW_PROGRESS`, шкала `PROGRESS_MAX`
= 100). Этого не было в вашем визарде — добавил, потому что для «уровня
достижения» доля от 100 % читается быстрее числа; `SHOW_PROGRESS = false`
убирает полосу, и остаётся ровно то, что было.

## Проверка

```
node dev/check.js               # изоляция рендера + четыре размера холста
node dev/preview.js 420 200     # обновляет preview.html
```

## Что проверено

* Четыре состояния в Chromium: значение есть (420×200), фильтр ничего не нашёл
  (прочерк и пояснение), длинное значение «1 234,5 %» (кегль уменьшается,
  разделитель разрядов сохраняется), маленький холст 300×140.
* `dev/check.js` проходит на четырёх размерах холста.

Не проверено вживую (нет доступа к инстансу DataLens): поведение
`Editor.generateHtml` на SVG-разметке и точные значения поля «Статус» —
если в датасете статус записан иначе (например, без запятой перед «%»),
поправьте строку в `STATUS_FILTER`.
