# 08. Вкладка «Структура»: внедрение иерархии в DataLens

Пошаговая инструкция для одной вкладки — той, что заменяет схему в drawio.
Общая сборка дашборда описана в `06-dashboard-build.md`; здесь только то,
что относится к иерархии «блок → проект → продукт».

Ориентировочное время — 40–60 минут, если основной датасет уже подключён.

---

## Часть 0. Что загружаем

Скрипт `prepare_dataset.py` создаёт три файла. Для этой вкладки нужны два:

| Файл | Гранулярность | Зачем здесь |
|---|---|---|
| `datalens_dataset.csv` | 267 строк — одно назначение | сводная таблица, древовидная карта, drill-down до сотрудника |
| `datalens_dataset_tree.csv` | 57 строк — продукт в разрезе руководителя | светофор незаменимости, карточки продуктов, столбец «Состав» |

Второй файл — не замена первому, а срез. Сводная таблица прекрасно строится
и из основного датасета; отдельный источник нужен там, где метрика уже
посчитана на уровне продукта («риск», «Состав») и агрегировать её в BI
неправильно.

Если не хотите вести два датасета — можно обойтись одним, основным. Тогда
пропустите чарты C7.3 и всё, что ссылается на поле «риск»: их место займёт
вычисляемое поле из части 2.

---

## Часть 1. Подключение и датасет

### 1.1. Загрузить файл

1. **Подключения → Создать подключение → Файлы**.
2. Перетащить `datalens_dataset_tree.csv`.
3. Проверить превью. Ожидаемые настройки разбора:
   - кодировка **UTF-8** (скрипт пишет BOM, DataLens определяет сам);
   - разделитель — **запятая**;
   - десятичный разделитель — **точка**;
   - первая строка — заголовки.
4. Сохранить под именем `hr_tree`.

> Если в превью числа встали строками, а `2550760.89` показывается как текст —
> значит подхватился разделитель «точка с запятой». Переключите вручную,
> пересохранять CSV не нужно.

### 1.2. Создать датасет

1. **Датасеты → Создать датасет**, источник — подключение `hr_tree`.
2. Проверить типы полей. Должно быть так:

| Поле | Тип | Агрегация |
|---|---|---|
| Блок, Проект, Руководитель, Продукт кратко | Строка | Нет |
| R4, R3, R2, R1, R0 | Целое число | Сумма |
| Состав, риск | Строка | Нет |
| людей, вакансий | Целое число | Сумма |
| ФОТ_мес, медиана_ЗП | Дробное число | Сумма / Среднее |

3. `медиана_ЗП` — поставить агрегацию **Среднее**, а не Сумма. Складывать
   медианы бессмысленно; при разворачивании до одного продукта разницы нет,
   но на уровне проекта Сумма даст заведомо неверное число.
4. Сохранить под именем `HR · Иерархия`.

### 1.3. Форматирование

Для `ФОТ_мес` и `медиана_ЗП`: **Количество знаков после запятой — 0**,
**Разделитель разрядов — включён**. Иначе в карточках будет
`2550760.89`, а не `2 550 761`.

## Часть 2. Поля, которые нужно создать

### 2.1. В датасете `HR · Иерархия`

**Поле-иерархия «Структура»** — тип «Иерархия», состав по порядку:

```
[Блок] → [Проект] → [Продукт кратко]
```

**`Команда`** — человекочитаемый состав вместо кода `4-3-2-3-0`:

```
CONCAT(
  IF([R4] > 0, STR([R4]) + ' рук · ', ''),
  IF([R3] > 0, STR([R3]) + ' вед · ', ''),
  IF([R2] > 0, STR([R2]) + ' адм · ', ''),
  IF([R1] > 0, STR([R1]) + ' исп · ', ''),
  IF([R0] > 0, STR([R0]) + ' стаж', '')
)
```

**`Риск незаменимости`** — если решили обойтись одним датасетом, это поле
воспроизводит столбец `риск` из скрипта:

```
CASE
  WHEN [людей] <= 1 THEN '1. Критично: 1 человек'
  WHEN [людей] = 2  THEN '2. Риск: 2 человека'
  ELSE '3. ОК'
END
```

Цифровой префикс нужен для сортировки легенды: без него DataLens выстроит
категории по алфавиту, и «Критично» окажется в середине.

**`Перевес администраторов`** — доля R2 в команде продукта:

```
[R2] / [людей]
```

Формат — процентный, 0 знаков. Метрика отвечает на вопрос из исходной
постановки: где под видом администрирования сосредоточен весь ресурс.

**`Продуктов`** — счётчик для карточек уровня проекта:

```
COUNTD([Продукт кратко])
```

### 2.2. В основном датасете

Если ещё не созданы по `06-dashboard-build.md`, добавьте иерархию с полной
глубиной — она нужна для drill-down до человека:

```
[Блок] → [Проект] → [Продукт кратко] → [Сотрудник]
```

## Часть 3. Чарты

Нумерация продолжает `06-dashboard-build.md`: вкладка 7.

### C7.1 — Сводная таблица «Состав команд» *(главный чарт вкладки)*

Тип: **Сводная таблица**. Датасет: **основной**.

```
Строки:    Блок
           Проект
           Продукт кратко

Столбцы:   Уровень роли

Значения:  COUNTD([Сотрудник])

Сортировка строк: SUM([ФОТ аллоцированный]) ↓
```

Это и есть бейдж из drawio, развёрнутый в подписанные столбцы. Строки
сворачиваются до уровня проекта одним кликом, всё выгружается в Excel.

Настройки, которые стоит включить:
- **Итоги по строкам** — численность продукта появится справа;
- **Итоги по столбцам** — сколько всего людей каждого уровня;
- цветовая заливка значений по столбцу `R2` — сразу видно продукты,
  где администраторов больше, чем всех остальных вместе.

### C7.2 — Древовидная карта «Где сосредоточен ФОТ»

Тип: **Древовидная карта**. Датасет: **основной**.

```
Размер:    SUM([ФОТ аллоцированный])
Разбивка:  Блок
           Проект
           Продукт кратко
Цвет:      AVG([Compa-ratio])
Подписи:   [Продукт кратко]
           COUNTD([Сотрудник])
```

Палитра цвета — расходящаяся, центр 1,00 (см. часть 2
`06-dashboard-build.md`). Площадь несёт деньги, цвет — справедливость
оплаты; вместе отвечают на вопрос «дорогой продукт — он дорогой
обоснованно?».

### C7.3 — Светофор незаменимости

Тип: **Столбчатая диаграмма с накоплением**, горизонтальная.
Датасет: **`HR · Иерархия`**.

```
Y:      Проект
X:      COUNT([Продукт кратко])
Цвет:   риск
```

Порядок цветов: «Критично: 1 человек» — красный, «Риск: 2 человека» —
жёлтый, «ОК» — нейтральный серо-синий. Ровно та информация, которой на
статичной схеме нет вообще: 24 продукта из 56 держатся на одном-двух людях.

### C7.4 — Карточки продуктов *(реестр)*

Тип: **Таблица**. Датасет: **`HR · Иерархия`**.

```
Столбцы:  Продукт кратко
          Проект
          Команда           (вычисляемое поле из 2.1)
          людей
          вакансий
          ФОТ_мес
          медиана_ЗП
          риск
```

Сортировка по умолчанию — `людей` по возрастанию, чтобы продукты с одним
человеком были сверху. Это рабочий список для разбора, а не витрина.

### C7.5 — Перевес администраторов *(диагностический)*

Тип: **Точечная диаграмма**. Датасет: **`HR · Иерархия`**.

```
X:       людей
Y:       Перевес администраторов
Размер:  ФОТ_мес
Цвет:    Проект
Подписи: Продукт кратко
```

Правый верхний угол — большие продукты, где больше половины команды
администраторы. Это кандидаты на проверку: либо роли в таблице проставлены
формально, либо продукт действительно ведут не те люди.

## Часть 4. Сборка вкладки

### 4.1. Селекторы

Три селектора в шапке, все — тип «Список», множественный выбор:

| Селектор | Поле | Датасет |
|---|---|---|
| Блок | `Блок` | основной |
| Проект | `Проект` | основной |
| Риск | `риск` | `HR · Иерархия` |

### 4.2. Связи между датасетами

Селекторы «Блок» и «Проект» должны фильтровать чарты из **обоих** датасетов.
DataLens не связывает их автоматически:

1. Открыть вкладку → **Связи** (иконка цепочки в правом верхнем углу).
2. Для селектора «Блок» проставить связь `по полю Блок` со всеми чартами
   датасета `HR · Иерархия`.
3. То же для «Проект».
4. Селектор «Риск» связать только с C7.3 и C7.4 — в основном датасете
   такого поля нет, и попытка связать даст ошибку.

Проверка: выбрать один блок в селекторе. Все пять чартов должны
перестроиться. Если C7.3 остался прежним — связь не проставлена.

### 4.3. Расположение

```
┌──────────────────────────────────────────────────────────┐
│  Селекторы: Блок · Проект · Риск                         │
├───────────────────────────────────┬──────────────────────┤
│                                   │                      │
│  C7.1  Сводная «Состав команд»    │  C7.3  Светофор      │
│        (главный, 2/3 ширины)      │        незаменимости │
│                                   ├──────────────────────┤
│                                   │  C7.5  Перевес       │
│                                   │        администраторов│
├───────────────────────────────────┴──────────────────────┤
│  C7.2  Древовидная карта «Где сосредоточен ФОТ»          │
├──────────────────────────────────────────────────────────┤
│  C7.4  Реестр продуктов                                  │
└──────────────────────────────────────────────────────────┘
```

Логика сверху вниз: сначала состав, потом риски, потом деньги, в конце
подробный список для работы руками.

### 4.4. Текстовый блок

Виджет «Текст» под селекторами — одна строка, чтобы вкладку не читали
неправильно:

> Один человек, работающий на двух продуктах, попадает в обе строки.
> Сумма по столбцу «людей» — 217, численность штата — 180. Для численности
> смотрите вкладку «Люди и зарплаты».

## Часть 5. Приёмка

Проверить до того, как показывать заказчику:

- [ ] Сумма `ФОТ_мес` по всем продуктам = **31 692 786,29 ₽** и совпадает
      с итогом вкладки «Обзор». Расхождение означает, что где-то включилась
      двойная агрегация.
- [ ] Сумма `людей` = **217**, а не 180. Если 180 — потерялись вторые
      назначения; если больше 217 — дубли в исходнике.
- [ ] Строк в C7.4 ровно **57**: 56 продуктов, из них ФССП дважды —
      его ведут два руководителя.
- [ ] Светофор: 7 «Критично», 17 «Риск», 32 «ОК».
- [ ] Селектор «Блок» перестраивает все пять чартов.
- [ ] Drill-down в C7.1 доходит до фамилии, а не обрывается на продукте.
- [ ] `медиана_ЗП` на уровне проекта выглядит правдоподобно — если там
      миллионы, агрегация осталась «Сумма».

## Часть 6. Обновление данных

Порядок при новой выгрузке:

1. Положить свежий `Datalens.xlsx` рядом со скриптом, запустить
   `python3 prepare_dataset.py`.
2. Посмотреть лист «Проверки». Строка **«Расхождение ФОТ, руб» должна быть 0**.
3. **Подключения → `hr_tree` → Заменить файл**. Датасет и чарты
   переподключать не нужно, если состав столбцов не менялся.
4. То же для основного датасета.
5. Открыть вкладку, пройти чек-лист из части 5.

Столбцы менять в скрипте, а не в DataLens. Поле, добавленное руками в
датасет, переживёт замену файла, но не переживёт пересоздание подключения,
и через полгода никто не вспомнит, откуда оно взялось.

## Часть 7. Доска карточек — Расширенный чарт

Код: [`editor/hierarchy-board.js`](editor/hierarchy-board.js).
Воспроизводит схему drawio один в один: колонка на проект, карточка на
продукт, полоска состава по уровням ролей.

### 7.1. Создать чарт

1. **Чарты → Создать чарт → Редактор → Расширенный чарт**.
2. Вкладка **Источники**: подключить датасет `HR · Иерархия`, добавить поля
   `Блок`, `Проект`, `Руководитель`, `Продукт кратко`, `R4`, `R3`, `R2`,
   `R1`, `R0`, `людей`, `вакансий`, `ФОТ_мес`, `риск`. Порядок значения не имеет —
   код ищет поля по названию.
3. Вкладка **JS**: вставить содержимое `hierarchy-board.js` целиком.
4. Сохранить.

### 7.2. Если чарт пустой

Формат ответа датасета между версиями DataLens немного отличается.
В коде есть строка:

```js
// module.exports = { title: { text: source.fields.join(' | ') } };
```

Раскомментируйте её, сохраните — чарт покажет заголовком те названия полей,
которые реально пришли. Дальше подстраивается только функция `readSource`,
остальной код от формата не зависит.

### 7.3. Что настраивается сверху файла

```js
var COL_WIDTH  = 236;   // ширина колонки проекта
var CARD_WIDTH = 212;   // ширина карточки
var SLOT       = 94;    // шаг между карточками по вертикали
var LEVELS     = [...]; // цвета уровней R4…R0
var THEME      = {...}; // цвета карточек, рамок риска, шрифты
```

Высота холста считается сама: `(макс. продуктов в колонке + 1,1) × SLOT`.
Ширина — `число проектов × COL_WIDTH`; когда колонок больше, чем влезает,
DataLens включает горизонтальную прокрутку внутри чарта.

### 7.4. Чего у этого чарта нет

- **Интерактивности.** Карточки не кликаются, тултипов нет — вся информация
  на самой карточке. Drill-down до сотрудника остаётся в C7.1.
- **Автоматической связи с селекторами.** Селекторы «Блок» и «Проект»
  фильтруют его как обычный чарт датасета, но любая нестандартная логика
  дописывается в коде руками.
- **Тёмной темы.** Цвета карточек заданы явно и не переключаются вместе
  с темой дашборда.
- **Устойчивости к переименованию полей.** Переименуете `ФОТ_мес` в
  датасете — чарт покажет ошибку с перечнем пришедших полей (для этого в
  `indexer` и брошено понятное исключение), но чинить придётся в коде.

Поэтому доска — витрина для первой вкладки, а рабочим инструментом остаётся
сводная таблица C7.1: в ней сортировка, drill-down до фамилии и выгрузка.

## Что осталось за рамками

**Дерево подчинённости.** Строится только после того, как в исходник
добавят столбец `ID руководителя` в той же нумерации, что и `ФИО (штат)`.
Сейчас руководители записаны фамилиями, сотрудники — идентификаторами,
и рёбра не смыкаются. Подробности — в `06-dashboard-build.md`, C4.5.
