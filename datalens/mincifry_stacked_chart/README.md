# Advanced-чарт DataLens: стек с суммой в итогах, стиль Минцифры

Код для типа визуализации **Advanced-чарт** в редакторе DataLens (Editor).
Столбчатый стек «Онлайн / Проактив / Рефакторинг» по годам с суммой над
каждым столбцом и оформлением в палитре дизайн-системы Госуслуг / Минцифры.

## Раскладка по вкладкам

| Файл | Вкладка |
|---|---|
| `Meta.json` | Meta |
| `Params.js` | Params |
| `Sources.js` | Sources |
| `Prepare.js` | Prepare |
| `Controls.js` | Controls |

Вкладок `Config` и `Highcharts` у Advanced-чарта нет — у него доступны ровно
эти пять.

## Как устроен Advanced-чарт

Это не конфиг готовой библиотеки графиков, а собственный рендер: вкладка
`Prepare` возвращает

```js
module.exports = {
    render: Editor.wrapFn({fn: function (options, ...args) { ... }, args: [...]}),
};
```

и функция `fn` возвращает разметку через `Editor.generateHtml()`. Отсюда два
следствия, которые определили структуру кода:

* **Код вне `wrapFn` исполняется на сервере**, код внутри — в браузере
  пользователя. Замыкания через эту границу не работают: `fn` не видит
  константы верхнего уровня файла.
* Поэтому вся подготовка данных идёт на сервере и складывается в один объект
  `model` (категории, серии, цвета, итоги, режим), который передаётся в
  `args`. Внутри `fn` только отрисовка SVG.

Первым аргументом в `fn` всегда приходят параметры чарта (`width`, `height`),
дальше — элементы `args`.

## Быстрый старт

В `Prepare.js` стоит `const DEMO = true` — чарт рисуется на зашитых цифрах
(131 / 235 / 98), можно принять оформление, не подключая датасет. Дальше:

1. `DEMO = false` в `Prepare.js`;
2. в `Meta.json` подставьте ID датасета вместо `PUT_YOUR_DATASET_ID_HERE`
   (берётся из URL: `.../datasets/<ID>`); в `Sources.js` он читается через
   `Editor.getId('servicesDataset')`;
3. названия полей правятся в двух местах: `SERIES_SPEC` / `X_FIELD` в
   `Prepare.js` и `fields` в `Sources.js`.

Ключ источника (`services` в `Sources.js`) должен совпадать с константой
`SOURCE_KEY` в `Prepare.js` — под этим именем данные приходят в
`Editor.getLoadedData()`.

## Сумма в итогах

Итог считается на сервере (`totals`) и рисуется отдельным `<text>` над верхним
сегментом столбца. В режиме долей столбцы нормируются к 100 %, а подпись
сверху остаётся абсолютной — иначе над каждым столбцом стояло бы «100 %».

Смежные решения по читаемости:

* подпись внутри сегмента скрывается, если сегмент занимает меньше 6 % стека
  (`minLabelShare`) или ниже 16 px — иначе цифры наезжают друг на друга, как
  «5» за 2027 год на вашем скриншоте;
* у каждого сегмента есть `<title>` — при наведении браузер показывает
  «2026 · Онлайн: 31 (13,2 %)»;
* верхний сегмент столбца скруглён сверху, остальные встык.

## Палитра и типографика

| Роль | Цвет |
|---|---|
| Основной синий | `#0D4CD3` |
| Акцент / внимание | `#EE3F58` |
| Успех | `#0FA958` |
| Текст | `#0B1F33` |
| Вторичный текст | `#5A7196` |
| Сетка | `#E4E8EE` |
| Ось | `#C9D2DE` |

Всё собрано в константе `BRAND` в начале `Prepare.js` и уезжает в рендер
внутри модели — менять в одном месте. Гарнитура — **Ubuntu** (шрифт
дизайн-системы Госуслуг) с системным запасом в стеке.

Это практическая реконструкция фирменного стиля по публичным материалам, а не
выгрузка из брендбука. Есть внутренний гайд — замените значения в `BRAND`,
остальной код трогать не нужно.

## Локальный предпросмотр

```
node dev/preview.js 960 540      # обновляет preview.html
```

Скрипт подставляет заглушку объекта `Editor`, выполняет `Prepare.js` и
сохраняет реальный результат рендера в `preview.html` — то есть проверяется
тот же код, который поедет в DataLens, а не его копия.

## Что проверено

* Рендер прогнан в Chromium на демо-данных в трёх режимах: абсолютные
  значения 960×540, доли 960×540, узкий контейнер 420×420. Ошибок нет, SVG
  валиден, итоги 131 / 235 / 98 совпадают с исходным визардом.
* Все файлы проходят `node --check`, `Meta.json` — валидный JSON.

Не проверено вживую (нет доступа к инстансу DataLens): поведение
`Editor.generateHtml` на SVG-разметке — санитайзер теоретически может резать
атрибуты. Если чарт отрисуется пустым, начните с `console.log` внутри `fn`
(логи из `wrapFn` идут в консоль браузера, а не в панель Console редактора).
