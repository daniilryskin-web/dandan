# 09. Расширенные чарты по вкладкам

> **Внимание: четыре чарта из пяти в этом документе устарели.**
>
> Они написаны как конфиги Highcharts. Advanced-чарт DataLens устроен
> иначе: он исполняет функцию `render` в песочнице QuickJS и рисует
> HTML/SVG, а Highcharts там недоступен вообще (доступны только `d3`,
> `d3-chord`, `d3-sankey`, `date-utils`).
>
> Переписан под настоящий API пока только **дерево структуры** —
> см. [`10-structure-tree-howto.md`](10-structure-tree-howto.md) и файлы
> `editor/structure-tree.*.js`. Скоркарта, доска карточек, разброс зарплат
> и матрица пересечений в существующем виде **не заработают**: их логика
> расчёта верна и переносится, но обёртку нужно менять на
> `Editor.wrapFn` + `Editor.generateHtml`.
>
> Ниже оставлено описание того, какие чарты зачем нужны и из каких полей
> считаются, — это по-прежнему актуально.

Пять чартов на Расширенном чарте (Advanced Chart) — по одному на вкладку,
только там, где штатный чарт DataLens не справляется. Код лежит в
[`editor/`](editor/), каждый файл самодостаточен: вставляется на вкладку JS
целиком, без внешних зависимостей.

| Вкладка | Чарт | Файл | Чего не умеет штатный |
|---|---|---|---|
| 0 · Обзор | Скоркарта направлений | [`scorecard.js`](editor/scorecard.js) | смешать рубли, доли, счётчики и предупреждения в одной плитке |
| 1 · Проекты и продукты | Доска карточек | [`hierarchy-board.js`](editor/hierarchy-board.js) | колонки-дорожки как в drawio |
| 2 · Люди и зарплаты | Разброс зарплат | [`salary-spread.js`](editor/salary-spread.js) | в DataLens нет типа «ящик с усами» |
| 3 · Загрузка и пересечения | Матрица пересечений | [`overlap-matrix.js`](editor/overlap-matrix.js) | связь между двумя значениями одного измерения |
| 4 · Оргструктура | Дерево структуры | [`structure-tree.js`](editor/structure-tree.js) | граф «родитель — потомок» связями, а не вложенностью |

Вкладки 5 «Экономика продуктов» и 6 «Качество данных» в списке нет
намеренно: первая заблокирована до появления метрик результата, второй
хватает сводной таблицы с условной заливкой.

---

## Общий порядок подключения

Одинаков для всех пяти:

1. **Чарты → Создать чарт → Редактор → Расширенный чарт**.
2. Вкладка **Источники** — подключить датасет и добавить поля из шапки
   файла. Порядок полей значения не имеет: код ищет их по названию.
3. Вкладка **JS** — вставить файл целиком.
4. Сохранить, положить на вкладку дашборда.

**Если чарт пустой.** В каждом файле есть закомментированная строка:

```js
// module.exports = { title: { text: source.fields.join(' | ') } };
```

Раскомментируйте и сохраните — чарт покажет заголовком названия полей,
которые реально пришли из датасета. Формат ответа между версиями DataLens
слегка отличается; подстраивается только функция `readSource`, остальной
код от него не зависит.

## Вкладка 0 · Скоркарта направлений

Плитка на проект: деньги, численность, трёхцветная полоса оценки зарплат
и предупреждения — хрупкие продукты, вакансии, стоимость выравнивания.
Предупреждения показываются только когда есть о чём: пустые чипы создают
ложное впечатление, что направление проверено.

**Источник** — основная таблица, агрегированная до проекта:

```
Измерения:  Блок · Проект
Показатели: Сотрудников        COUNTD([Сотрудник])
            ФОТ                SUM([ФОТ аллоцированный])
            Недоплата          COUNTD(IF([Группа оценки]='Недоплата',[Сотрудник],NULL))
            Соответствует      COUNTD(IF([Группа оценки]='Соответствует роли',[Сотрудник],NULL))
            Переплата          COUNTD(IF([Группа оценки]='Переплата',[Сотрудник],NULL))
            Вакансий           SUM([Вакансия])
            Хрупких продуктов  COUNTD(IF([Людей на продукте]<=2,[Продукт ключ],NULL))
            Доплата            SUM([Доплата до порога])
```

Настройки сверху файла: `TILE_W`, `TILE_H`, `COLUMNS`.

## Вкладка 2 · Разброс зарплат

Ящик с усами по проектным ролям плюс точки людей, окрашенные по оценке
зарплаты. Коробка рисуется через `chart.renderer` — это ядро Highcharts,
модуль `highcharts-more` не нужен, и его наличие в вашей инсталляции роли
не играет.

Три вещи, из-за которых чарт сходится с листом «Роли»:

- **Квартили с линейной интерполяцией** — тот же метод, что `КВАРТИЛЬ.ВКЛ`
  в Excel и `quantile()` в скрипте. Другой метод дал бы другие числа.
- **Усы до крайних значений внутри забора**, а не до самого забора
  `Q1 − 1,5·IQR`: иначе ус висит там, где никто не получает.
- **Плоский тариф** (`IQR = 0`) — коробка не рисуется вообще, остаётся
  только линия медианы и подпись «плоский тариф». Роли на единой ставке
  иначе выглядели бы так, будто у них нулевой разброс по ошибке.

Джиттер точек детерминированный, а не случайный: при случайном одна и та
же зарплата прыгала бы по горизонтали при каждой перерисовке.

**Источник** — основная таблица, одна строка на человека:

```
Фильтр:     [В анализе справедливости] = 1
Измерения:  Проектная роль · Уровень роли № · Сотрудник · Группа оценки
Показатель: ЗП
```

## Вкладка 3 · Матрица пересечений

Проекты по обеим осям, в ячейке — сколько людей работает в обоих
направлениях. По диагонали численность самого проекта.

**Честно о пользе на ваших данных.** Совмещённых людей всего **8 из 180**,
поэтому матрица почти пустая: восемь непустых ячеек из 132 возможных.
Максимальное пересечение — 3 человека между «Ядром ЕПГУ» и «Мобильными
приложениями». Если картина не изменится, вкладке хватит обычного списка
этих восьми человек, а матрицу имеет смысл ставить, только когда
совместительство станет массовым.

**Источник** — основная таблица без агрегации:

```
Фильтр:    [Вакансия] = 0
Измерения: Сотрудник · Проект
```

## Вкладка 4 · Дерево структуры

Четыре уровня со связями, слева направо:

```
Ответственный за направление → Проект → Руководитель → Продукт
```

На каждом узле — состав команды по уровням ролей: полоса R4…R0 и те же пять
чисел, что стоят в бейджах drawio-схемы (`4-3-2-3-0`). У продукта состав
свой, у руководителя, проекта и направления — сумма по ветке. Рамка продукта
красная при одном человеке и жёлтая при двух, рядом с численностью
показываются вакансии.

**Почему руководитель — полноценный уровень, а не подпись.** По данным
каждый из 18 руководителей относится ровно к одному направлению и одному
проекту, а у продукта руководитель один. Исключение единственное — ФССП
в «Окружающем мире» ведут двое, и продукт честно попадает в обе ветки
двумя узлами. Если в будущем руководитель начнёт вести два проекта, дерево
покажет его дважды: это не сбой, а отражение того, что записано в таблице.

**Это дерево структуры работ, а не подчинённости.** Дерево «кто кому
подчиняется» строится тем же кодом, но требует столбца `ID руководителя`
в той же нумерации, что и `ФИО (штат)`. Сейчас руководители записаны
фамилиями, сотрудники — идентификаторами, и рёбра между ними не смыкаются.

**Источник** — датасет «HR · Иерархия»:

```
Измерения:  Блок · Проект · Руководитель · Продукт кратко · риск
Показатели: R4 · R3 · R2 · R1 · R0 · людей · вакансий · ФОТ_мес
```

Высота холста считается от числа продуктов (`totalRows × ROW`), ширина —
от `COL_X` и `NODE_W`. При 57 строках получается около 2000 px, поэтому
чарт стоит класть на всю ширину вкладки и не соседствовать с ним.

## Что проверено, а что нет

Все пять конфигов прогнаны локально на Highcharts 13 с реальными данными
выгрузки: 56 продуктов, 180 сотрудников, 12 проектов. Отрисовка, раскладка
и подписи проверены на скриншотах.

Не проверено одно — формат ответа `Editor.getLoadedData()` в вашей
инсталляции DataLens. Это единственное место, где может потребоваться
правка, и на него рассчитана строка DEBUG.

Три ошибки, которые вылезли только на рендере и уже исправлены — они же
самые вероятные грабли, если будете писать свои чарты:

1. **`startOnTick` / `endOnTick`.** По умолчанию включены: Highcharts
   расширяет `min`/`max` до целых делений, и заданный шаг слота в 190 px
   превращался в 143. Отключать обязательно, если позиционируете элементы
   по сетке.
2. **`verticalAlign: 'middle'` у HTML-подписей.** Карточки разной высоты,
   и центрированная высокая наезжает на соседа сверху. Нужно `'top'`
   со сдвигом `y: -SLOT / 2`.
3. **`getBBox()` в обработчике `render`.** Возвращает ноль — элемент ещё
   не измерен браузером. Ширину текста приходится оценивать по числу
   символов.

## Общие ограничения Расширенных чартов

- **Нет интерактивности**, кроме той, что напишете сами. Тултипы есть
  только в чарте разброса.
- **Нет тёмной темы**: цвета заданы явно и с темой дашборда не
  переключаются.
- **Молча ломаются при переименовании поля** — точнее, показывают
  исключение со списком пришедших полей (в `indexer` оно брошено
  специально), но чинить нужно в коде.
- **Селекторы дашборда** фильтруют их как обычные чарты датасета, а любая
  нестандартная логика дописывается руками.

Поэтому Расширенные чарты — витрина. Рабочими инструментами остаются
сводные таблицы и реестры: в них сортировка, drill-down до фамилии
и выгрузка в Excel.
