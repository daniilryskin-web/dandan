# 04. Сборка в DataLens, доступы и дорожная карта

---

## 1. Пошаговая сборка

### Шаг 1. Подготовить источник (30–60 мин)

1. Привести таблицу к шаблону `templates/assignments_template.csv`.
2. Добавить и заполнить: `Доля занятости`, `Грейд`, `Первичное назначение`, `Дата среза`.
3. Прогнать проверки из `01-data-model.md`, раздел 1.5. **Все должны быть зелёными до загрузки** — чинить данные через формулы в BI дороже и менее надёжно.
4. Завести листы-справочники: `employees`, `products`, `market` (шаблоны в той же папке).

### Шаг 2. Подключение

**Google Sheets:** Подключения → создать → Google Sheets → вставить ссылку на таблицу с доступом «по ссылке — читатель».

⚠️ **Важно про приватность.** Ссылка «доступ по ссылке» на таблицу с зарплатами — это публичная ссылка. Тот, кто её получит, увидит всё. Варианты:
- расшарить только по конкретным адресам и подключаться через OAuth-авторизацию коннектора (предпочтительно);
- либо хранить зарплаты в отдельной таблице с ограниченным доступом;
- либо не использовать Google вовсе — загрузить файл прямо в DataLens.

Оцените риск честно: утечка зарплатной таблицы — самый частый и самый разрушительный инцидент в такого рода проектах, и восстановить доверие в команде после него почти невозможно.

**Файл:** Подключения → создать → Файлы → загрузить CSV/XLSX. Полностью внутри контура Яндекса, но обновление ручное.

### Шаг 3. Датасет

1. Датасеты → создать → выбрать подключение → перетащить лист `assignments` как основную таблицу.
2. Добавить справочники и настроить связи на вкладке «Связи»:
   - `assignments.ID сотрудника` → `employees.ID сотрудника` (**Left join**)
   - `assignments.Проект` → `projects.Проект` (Left join)
   - `employees.Роль + Грейд` → `market.Роль + Грейд` (Left join)

   Left join, а не inner: иначе сотрудник, для роли которого нет рыночной вилки, молча исчезнет из дашборда. Это ровно тот класс ошибок, который замечают через месяц.
3. Вкладка «Поля» — завести все вычисляемые поля из `02-fields.md`. Порядок: сначала группа 1 (ключи), потом 2–3, потом 4 (справедливость зависит от предыдущих).
4. Вкладка «Параметры» — завести параметры из группы 3.1.
5. Для каждого поля задать формат отображения: деньги — тысячи с ₽, отношения — 2 знака, доли — проценты.
6. Настроить иерархию для drill-down: `Проект` → `Продукт` → `Роль` → `ФИО`. Один клик по столбцу проекта проваливает в его продукты — экономит половину селекторов.

### Шаг 4. Чарты

Собирайте в порядке вкладок из `03-charts.md`. Практические советы:

- **Начните со вкладки 2** (люди и зарплаты). Она даёт результат, ради которого всё затевалось, и после неё сразу видно, правильно ли посчитаны базы сравнения.
- Первым делом проверьте `Compa-ratio` на 3–5 знакомых людях вручную. Если для кого-то цифра выглядит странно — почти всегда дело в грейде или в LOD-выражении, и лучше это выяснить на пятом чарте, а не на тридцатом.
- Дублируйте чарты через «Сохранить как» и меняйте одну метрику — быстрее, чем собирать заново.
- Именуйте чарты по схеме `[Вкладка] Название`, например `[2] Compa-ratio по сотрудникам`. Через месяц в списке из 30 чартов это будет единственный способ что-то найти.

### Шаг 5. Дашборд

1. Создать дашборд, добавить вкладки (0–6).
2. На каждую вкладку — строку селекторов **сверху**, привязанных к датасету, с включённым «Множественный выбор».
3. Важно: селекторы должны влиять на все чарты вкладки. В DataLens связи настраиваются через «Связи» в меню дашборда — проверьте каждый чарт, по умолчанию связывается не всё.
4. Добавить текстовые виджеты с описанием вкладки и подсказками, как читать чарты. Это не украшательство: дашборд без подписей читают неправильно, и вы будете объяснять одно и то же на каждой встрече.
5. Настроить переходы: клик по проекту в C0.1 → переход на вкладку 1 с подставленным проектом (в DataLens это делается через параметры и «Действия по клику»).

### Шаг 6. Права доступа — обязательный шаг, не опциональный

Дашборд с зарплатами всей компании — самый чувствительный документ, который у вас будет. Уровни:

| Кто | Что видит |
|---|---|
| Вы, HR, финансы | Всё |
| Ответственный за направление | Только своё направление, с зарплатами |
| Руководитель | Только своих подчинённых |
| Остальные | Не имеют доступа вовсе, либо «обезличенная» копия |

**Row-Level Security в DataLens** настраивается в датасете (RLS в свойствах поля). Синтаксис примерно такой:

```
'user1@company.ru': Проект А
'user2@company.ru': Проект Б, Проект В
'hr@company.ru': *
```

Проверять RLS обязательно через режим «Просмотр от имени пользователя» — на словах она всегда настроена правильно, а на практике почти всегда с первого раза протекает.

**Обезличенная копия** для широкого доступа: отдельный дашборд на том же датасете, но без полей `ЗП`, `Compa-ratio`, `Отклонение ₽`. Оставить только загрузку, состав команд и пересечения. Такой дашборд полезен всем и не создаёт рисков.

## 2. Дорожная карта

### Неделя 1 — рабочая версия
- Доработать таблицу (доли, грейды, флаг первичного назначения).
- Датасет + поля групп 1–4.
- Вкладки 0, 1, 2.
- Настроить RLS.
- **Результат:** отвечаете на вопросы «сколько стоит каждое направление» и «где перекосы в оплате».

### Неделя 2 — полный контур 1
- Вкладки 3, 4, 6.
- Параметры и what-if калькулятор индексации.
- Первый разбор находок с руководителями.
- **Результат:** дашборд закрывает всю аналитику, которую вообще можно извлечь из данных о занятости и ФОТ.

### Месяц 2 — рынок и результат
- Собрать рыночные вилки по 10–15 ключевым ролям (Хабр Карьера, getmatch, отраслевые обзоры).
- Договориться с владельцами продуктов о метрике результата (хотя бы одной).
- Вкладка 5.
- **Результат:** появляется числитель. С этого момента можно говорить об эффективности, а не только о затратах.

### Месяц 3+ — динамика
- Ежемесячные срезы, вкладка динамики (группа полей 8).
- Регулярный цикл: раз в квартал — ревью зарплат по дашборду, раз в месяц — проверка загрузки.
- **Результат:** дашборд становится инструментом управления, а не отчётом. Видно не только «как есть», но и «куда движемся».

## 3. Чек-лист приёмки

**Данные**
- [ ] Сумма долей по каждому сотруднику в диапазоне 0.95–1.05
- [ ] Ровно 12 проектов, у каждого ровно один ответственный
- [ ] У каждого сотрудника ровно одна зарплата во всех его строках
- [ ] Грейд проставлен всем (или у «Не указан» осознанно малая доля)
- [ ] Нет дублей назначений
- [ ] Вкладка 6 пустая, индекс полноты 100%

**Расчёты**
- [ ] `ФОТ аллоц.` = `ФОТ уник.` (сходятся два независимых способа)
- [ ] `COUNTD(ФИО)` = `SUM(Первичное)`
- [ ] Compa-ratio проверен вручную минимум на 5 сотрудниках
- [ ] Базы сравнения не «съезжают» при выборе проекта в селекторе (проверить необходимость `BEFORE FILTER BY`)
- [ ] «Уровень сравнения» показан в реестре — видно, где выборка мала

**Оформление**
- [ ] Ни один чарт не красит 12 проектов в 12 цветов
- [ ] Ни одного чарта с двумя осями Y
- [ ] Все деньги отформатированы в тысячах/миллионах с ₽
- [ ] Светофор ЗП несёт три цветовых класса, пятиуровневая детализация — текстом и стрелками
- [ ] У каждого чарта есть подпись, объясняющая, что в нём искать
- [ ] Селекторы стоят одной строкой сверху и влияют на все чарты вкладки
- [ ] Проверено в тёмной теме

**Доступы**
- [ ] RLS настроена и проверена в режиме «от имени пользователя»
- [ ] Ссылка на исходную таблицу не публичная
- [ ] Решено, кому доступна обезличенная копия

## 4. Как этим пользоваться дальше

Дашборд сам по себе ничего не меняет. Работает регулярный цикл:

**Ежемесячно (15 минут):** открыть вкладку 6 (данные в порядке?), затем вкладку 3 (кто перегружен, кто недогружен). Поправить назначения.

**Ежеквартально (1–2 часа):** вкладка 2. Пройти список «требует внимания» построчно. По каждому — решение: повысить, оставить, разобраться. Посмотреть на цифру стоимости выравнивания и решить, какую часть закрываете в этом квартале.

**Раз в полгода:** вкладки 4 и 5. Оргструктура и экономика меняются медленно, чаще смотреть смысла нет.

**Перед бюджетированием:** what-if калькулятор. Три сценария индексации, три цифры — и разговор с финансами идёт по числам, а не по ощущениям.

## 5. Что этот дашборд не покажет — и об этом стоит помнить

Честность в отношении границ инструмента полезнее любого дополнительного чарта:

- **Индивидуальную производительность.** Ни зарплата, ни загрузка не говорят, насколько хорошо человек работает. Compa-ratio 0.7 может означать и недоплату, и справедливую оплату слабого сотрудника. Дашборд поднимает вопрос, ответ на него даёт руководитель.
- **Качество работы команды.** Даже с выручкой на FTE вы измеряете результат, а не то, как он получен. Команда может выдавать выручку и одновременно накапливать техдолг, который взорвётся через год.
- **Причины отклонений.** Дашборд показывает, что аналитик получает на 30% выше медианы. Почему — потому что он единственный, кто знает легаси-систему, или потому что удачно поторговался при найме — знаете только вы.
- **Справедливость по существу.** Compa-ratio — это соответствие внутренней норме. Если сама норма перекошена (например, исторически недоплачивают всей функции), дашборд покажет всех «в норме». Отсюда важность рыночных вилок как внешнего якоря.

Правильная формулировка того, что делает этот дашборд: **он превращает вопросы, которые раньше не возникали, в конкретный список из 10–15 человек и 3–4 продуктов, по которым нужно принять решение.** Само решение остаётся за вами — и это нормально.
